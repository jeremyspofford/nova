# Interstitial Research: adaptations from the packet

The packet's `SKILL.md` (this folder, unchanged) was written for the Agent Skills standard and for
subsystems the packet assumed. The shipped skill is `skills/interstitial-research/SKILL.md`. Every
difference is below, with the evidence in current main (line numbers are origin/main at branch
time) and how to reverse it. Nothing here loosens a privacy rule, an ingest rule, a never-trigger
case or a threshold.

| # | Adaptation | Why (evidence) | Reversible: how |
|---|---|---|---|
| 1 | Front matter keeps `name` and `description`, and adds a one-line `when:` and `words:` (research, deep dive, deep-dive, investigate, what are the options, what is everyone missing, options for). | Every installed skill is listed in every prompt as `- id: name. Use when: <when or about>` (src/context.js:25), and `when` falls back to the whole description (src/skills.js:60). The packet's description is about 700 characters; the short `when` keeps the always-listed line small. `words` is Nova's keyword trigger (src/skills.js:211, runner.js:321). | Delete `when:` and `words:`; the description loads as-is (tests/skills.test.js:126). |
| 2 | `Skills.match` matches a phrase as consecutive words; a single word matches exactly as before. | Matching compared single words only (src/skills.js:212–213), so "deep dive" or "what are the options" could never match. | Revert the three lines in `match()`; single-word skills behave identically either way (tests/skills.test.js matching test). |
| 3 | §2 search order: web_search, then web_fetch. No connector-first step, no Nova browser step, no transcripts. | The chat agent has only web_search (DuckDuckGo) and web_fetch (src/tools.js:153 and web_fetch above it); there is no chat browser-read tool and no transcript tool. | Re-add the steps when such tools exist in the chat tool set. |
| 4 | The field map is written by the model in a fenced `interstitial-field-map` block in a fixed JSON shape, validated in code (src/interstitial.js `validateFieldMap`). Not a Decision Service template. No cache. | Decision Service answers are probabilities only (Noul/Choice/Score/Box, src/core/decision-service/types.ts:12–28); it cannot generate a field map. | Replace with a template if the service ever generates; the record shape stays. |
| 5 | Invalid or missing field map: Quick depth, core only, and the record says why (`depth_why`). Depth follows the number of adjacent fields (1 Quick, 2–3 Standard, 4–5 Deep). | The schema has no depth field (lead's schema); the packet's depth bands are defined by adjacent-field counts (§3). | Add an explicit `depth` key to the schema and read it in `depthOf`. |
| 6 | The verification battery is one Decision Service call per claim (claims listed by the model in a fenced `interstitial-claims` block), not batched. | Each template has fixed questions per call (types.ts:88–108, registry.ts); a battery for N claims would need N×4 questions in one template, which the registry can't express. Tev1 takes at most 64 questions per request anyway. | Batch when the service supports per-call question sets. |
| 7 | A claim may cite only a page fetched in this run; the excerpt sent to verify-transfer is that page's screened extract (taint kept in the record). A claim citing anything else, or a page the ingest screen blocked, is discarded without a model. | The packet's §D.2 citation check; reads are screened and tainted in runner.js:484–489. "Quarantined by ingest" in the packet maps to Nova's `block` verdict (src/core/ingest/screen.ts:470–473); a `quarantine` extract is content with instructions removed, so it may be cited. | Tighten to pass-only in `Interstitial.verify`. |
| 8 | The outbound check runs per web_search query, in the runner, after the ingest gate's deterministic check (runner.js:659). Its default (no trusted answer) is withhold, so until the template passes an eval on a seat no search leaves from a run that follows the skill. | Lead's decision: fail closed; the deterministic `ingest.outbound` stays in place (runner.js:659–660). | None needed: trust follows the existing eval verdicts (verdicts.ts) per version × seat × model. |
| 9 | Local-only: no outside research; Nova answers from its self-knowledge and says so. | LOCAL-ONLY removes the web tools entirely (src/tools.js:470 `withinPrivacy`), and both templates are `feature: 'private'` (never a cloud seat in a local mode, service.ts:115–118). | None: this is the packet's own rule, made concrete. |
| 10 | Dead ends live in `~/workspace/interstitial/dead-ends.md`, read and written by the model with read_file/write_file. | There is no skill-data store; write_file writes only in workspace/ (src/tools.js:110). Removing the skill deletes `~/workspace/interstitial/` (skills.js `removeData`, backups `SKILL_DATA`), and the folder is kept out of the home's git history (src/home.js UNTRACKED). | Move the folder and update `SKILL_DATA`. |
| 11 | Proposals: a Work Ledger task (owner `workspace`, approval tier 2) that waits in the existing Approvals list. Approving writes the proposal with its run records to `~/workspace/interstitial/proposals/`; it applies nothing; the goal says "apply as a new skill version via a builder PR". | There is no drafts inbox and no propose-from-chat flow; `ledger.approve` (src/core/ledger.ts:232) and the workspace worker (src/core/workspace.ts:71, writes only inside the workspace) exist. | Point `#propose` at a drafts inbox when one exists. |
| 12 | The self-improvement scout is dropped (§1 trigger, §3 Deep, §8). | There is no scout and no research classifier in main. | Re-add when a scout exists. |
| 13 | Cost: overhead is skill tokens over core tokens within the run (a model call counts to the skill when it follows a non-core matrix search or a claim check); searches are recorded core vs skill. | caps.meter reports tokens per run (src/core/caps/index.ts:245–297) with no per-purpose split; a searches-only ratio would breach Quick's 15% on every run by construction. | Change `Interstitial.tokens`/`record` once calls can be attributed directly. |
| 14 | §1 adds one line: if loaded for a never-trigger case, say so and answer the ordinary way. | A `words:` match can load it on a message that also says "research" in passing; the never-trigger list itself is unchanged. | Delete the line. |
| 15 | Feature flag `features.interstitial` (nova.config.json) / `NOVA_FEATURE_INTERSTITIAL`, default off: the skill is hidden from list, match, load and install, and no hook runs. | No feature-flag mechanism existed (src/config.js). | Set the flag; remove `FEATURE_SKILLS` to drop the gate. |
