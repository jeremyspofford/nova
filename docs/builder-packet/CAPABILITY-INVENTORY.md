# CAPABILITY INVENTORY — target vs. existing

Status key: **Have** (exists and verified) · **Partial** (exists, needs work) · **New** (build) · **Later** (specified, not in early milestones).

**Verified at M0 (2026-10-29) against the code, not the docs.** Era 2 = `origin/main` HEAD `04512c07` (plain JS, Node built-ins only, 127 tests). Era 1 = last Era 1 commit `6e2cf142` (TypeScript monorepo + Rust `novad`, ~465k lines TS + 24k Rust, all four CI jobs green on GitHub at that commit; deleted from the tree by `7ea842b5` "clean slate"). Evidence paths for every row are in `docs/inventory/M0-DELTA.md`. Rows marked **▲ corrected** changed at M0; rows marked **● M1** changed when the M1 core landed (`src/core`, 2026-10-29); **◆ M2** when triggers, memory and triage landed; **■ M3** when design systems and the PWA landed. Rows marked **★ M4** changed when the device mesh landed (M4a: enrollment, the registry, sessions, the access policy).

"Reuse" names the component a milestone should start from. Reuse is per component: Era 1 code is ported in only with its tests and only where it fits the contracts here; its dependency footprint (React, Electron, Fastify, drizzle, QuickJS) does not come with it.
