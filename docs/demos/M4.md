# M4 — Demo

Install a plugin, run its slash command, open the terminal pane (`docs/17` M4), then walk the
rest of extensibility and the workspace: hooks, MCP Apps, bundles, panes, files, import and
usage.

## Preconditions
- `npm ci && npm run build`; a fresh data directory. No network or model is needed: the offline
  Mock provider drives tool calls from lines like `/tool mcp:sample.fetch_status {"url":"…"}` and
  answers other messages with "You said: …".
- Optional: Docker or Podman with an image that has Node and Perl, pulled beforehand and named in
  `NOVA_SANDBOX_IMAGE` (for example `node:24-slim`). Terminals and the sample plugin's command
  hook (`node hooks/check.mjs`) run in that container. Without one, terminals say the Hub has no
  sandbox, and the trusted hook fails closed: every call it guards is blocked.
- The sample bundle packed as a file: `(cd examples/bundles/hello && zip -qr /tmp/hello.mcpb .)`.
- A folder to import: `mkdir -p /tmp/nova-import/skills/standup`, then a `SKILL.md` in it with
  front-matter `description: Write a three-line stand-up update.`, an `AGENTS.md` with a line of
  instructions, and `/tmp/nova-import/mcp.json` containing
  `{"mcpServers":{"echo":{"command":"node","args":["echo.js"],"env":{"ECHO_API_TOKEN":"demo-value-1"}}}}`.

## Script
1. `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`, open the setup link, **Finish setup**,
   **Skip setup**. Put a file in `$NOVA_DATA_DIR/workspace/notes.txt`.
2. **Install the sample plugin.** Settings → Plugins & skills → Catalog: add a catalog named
   "Local examples" whose location is the absolute path of `examples/catalog` (the built-in
   sample catalog may list it already). Search "sample" → **Install** on "Sample plugin". The
   install screen says Unverified, lists "Reach these hosts on the network: api.example.com", the
   skills, the `sample` MCP server and the hook `hook:com.example.sample.check-fetch` with its
   event, command, timeout and full hash. **Install** stays disabled until **I trust its source;
   install it unverified** is ticked. Leave **Trust … now** unticked and install. The plugin row
   says Unverified and "Hooks need trust"; Settings → Tools & MCP shows the `sample` server
   Connected.
3. **Run its slash command.** New chat, type `/gre`: the Slash commands list offers `/greet`.
   Choose it, type `Ada`, send. The turn loads the skill ("The user loaded this skill with
   /greet."); the Mock provider answers "You said: Ada", where a real model would greet Ada.
4. **Permissions are enforced.** Send
   `/tool mcp:sample.fetch_status {"url":"https://api.example.com/health"}`: it asks (the sample
   server's default is ask); **Allow once** → "Would check api.example.com". Send the same tool
   with `https://not-declared.example.net/x`: the tool card is denied at once with
   "not-declared.example.net is not a host this plugin declared", and there is no approval to
   give.
5. **Trust a hook, edit it, trust it again.** Settings → Plugins & skills → Hooks: the hook says
   Needs trust. **Trust…** shows From, Event, Runs, the same hash as the install screen, Can and
   Cannot → **Trust**; it is Trusted. Now edit the installed hook, for example change
   `timeoutMs` to `5000` in `$NOVA_DATA_DIR/plugins/com.example.sample/1.0.0/hooks/hooks.json`,
   and reload: Needs trust, "Changed since you trusted it", "timeout 5 s", and the plugin says
   "Hooks need trust" again. Trust the new hash. Changing the file back does not trust it again.
   With a sandbox, step 4's undeclared host is now blocked by the hook first ("The sample plugin
   may only reach api.example.com, …"); without one, the trusted hook fails closed and blocks
   every `fetch_status` call.
6. **Open its MCP App.** The sidebar's **Apps** lists "Sample panel" (`/apps/<id>` opens it as a
   page). Back in the chat, Inspector → **Apps** → **Open Sample panel**: the frame shows the
   panel inline with "Sample plugin" and Unverified. **Run panel action**: an approval card
   appears in Nova's chrome below the frame ("Not from your message", since an app's call carries
   no user instruction); **Allow once** and the panel shows the result. **Full screen** opens a
   dialog with focus on **Exit full screen**; Esc returns. **Picture in picture** floats the
   panel; drag it, or use **Move** and the arrow keys; switch chats or Inspector tabs and it stays
   on screen. Close it with its close button.
7. **Install an unsigned bundle.** Settings → Tools & MCP → **Install a bundle** →
   `/tmp/hello.mcpb`. "Install Hello (sample bundle) 1.0.0?" lists its tools, a form for
   Greeting, API key (a password field) and Notes folder, and the hosts and files it may use.
   Enter an API key such as `hello-demo-key-1`, tick **I trust where this bundle came from;
   install it unverified**, **Install**. The `nova-hello` row says Unverified, "bundle nova-hello
   1.0.0", Connected. In a chat, `/tool mcp:nova-hello.settings_check {}` → **Allow once** → "an
   API key is set (16 characters)". `grep -rl hello-demo-key-1 "$NOVA_DATA_DIR"` prints nothing:
   the key is only in the encrypted vault (or the OS keychain with `NOVA_SECRETS=keychain`).
8. **Terminal and files.** Ctrl/Cmd+J (Alt+J in a browser tab) opens the bottom panel with a
   terminal: `stty size`, then resize the panel and run it again. Ctrl+` from inside the terminal
   closes the panel and returns focus. Inspector → **Files** → `notes.txt` opens it in an editor
   pane; edit and press Ctrl/Cmd+S: it saves with no approval card (your own action). Append a
   line to the file from a shell, edit again and save: the editor offers **Reload and discard my
   changes** or **Save mine anyway**.
9. **Save and restore a layout.** Layout menu (top bar) → **Split right**, choose Editor; command
   palette → **Add terminal pane**; drag a splitter or use the arrow keys on it. Stop the Hub
   (Ctrl+C), start it again with the same `NOVA_DATA_DIR` and reload: the chat, editor and
   terminal panes come back with their sizes. **Reset layout** returns to the single chat pane.
10. **Import from a folder.** Settings → Import (or the palette's **Import from another
    assistant**): enter `/tmp/nova-import` → step 2 lists the instruction file, the `standup`
    skill and the `echo` MCP server → step 3 shows `ECHO_API_TOKEN` masked with the `secret://`
    reference it becomes, and that the server stays off → **Import**. The `standup` skill appears
    under Skills, `echo` in Tools & MCP disabled, `AGENTS.md` becomes a project's instructions,
    and Import records lists each item. Importing again marks them "already imported".
11. **Profile and usage.** Settings → Profile & usage: set a display name and a username, upload
    a PNG avatar. Usage (last 7 days) shows today's tokens and turns from this demo, day bars with
    a table view, the streak and active days, the longest task linking to its chat, and tables by
    model (the mock model) and by project.

## Expected results
- Nothing from a plugin, bundle or import runs or is enabled without an explicit choice: the
  sideload box, the hook's hash trust, the bundle's sideload box, and disabled imports.
- A host the plugin did not declare is denied with a clear reason; an app's tool call asks; a
  hook whose file changed waits for trust; a guard hook that cannot run blocks.
- The bundle's key and the imported token are in the vault only; no file under the data
  directory holds them.
- The pane layout survives a Hub restart; the terminal runs in the sandbox or says it cannot.
- No serious or critical accessibility violations on the Plugins & skills, Apps, App frame,
  Tools & MCP and Profile & usage screens.
