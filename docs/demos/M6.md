# M6 — Demo

An always-on agent books a meeting on a mock calendar and asks before the invite goes out; it
researches on its own (reading only), answers on Slack without leaking a DM into a shared
channel, wakes on a signed calendar event, and works on its own computer, which you can take over.
Everything runs offline on the Mock provider; the calendar and Slack are local mocks from `e2e/`.

## Preconditions
- `npm ci && npm run build`; a fresh data directory. The Mock provider calls the tools named on
  lines like `/tool mcp:calendar.list_events {}` and answers other text with "You said: …".
- The mock calendar MCP server, `e2e/support/calendar-mcp-server.mjs` (tools `list_events`,
  `create_event`, `send_invite`; events `invite.received`). With
  `--control /tmp/nova-cal.json` it also listens on a loopback port for the demo's own controls
  (`POST /emit` sends a signed `invite.received`).
- Optional, for the Slack step: the mock Slack in `e2e/support/mock-slack.ts`, with the Hub
  started with `NOVA_SLACK_API_BASE` pointing at it.
- Optional, for the browser step: Chromium for Playwright (`npx playwright install chromium`) on
  the Hub's machine. Without it the browser panel says why the browser cannot start.

## Script
1. `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`, open the setup link, **Finish setup**,
   **Skip setup**.
2. **Computers.** Sidebar → **Computers**: under "Settings for every computer", new agent
   computers run on **Cloud** (the mock cloud). Settings → **Network** shows the egress mode
   (allowed hosts only), the allow and block lists and the empty decision log.
3. **The calendar.** Settings → **Tools & MCP** → **Add server**: name `calendar`, command `node`,
   arguments `e2e/support/calendar-mcp-server.mjs --control /tmp/nova-cal.json`, no default
   approval. It connects with three tools. Tick **Reads only** on `list_events` only: research may
   now read the calendar and nothing else of it.
4. **The agent.** Sidebar → **Agents** → **New agent**: name "Scout", responsibility "Keep my week
   in order", proactive research on. The agent page opens with its conversation; the **Computer**
   tab shows its cloud computer.
5. **Research that only reads.** Give the responsibility the details
   `/tool mcp:calendar.list_events {}` (the Mock acts on that line; the form's details field is
   one line, so set it with `PATCH /api/v1/agents/<id>/responsibilities/<rid>` when it needs
   more) and press **Research now**. **Suggestions** gets a finding with the
   calendar's events; nothing asked, nothing written.
6. **Book a meeting, ask before sending.** In Scout's conversation send:

   ```
   /tool mcp:calendar.create_event {"title":"Design review","start":"2026-10-20T10:00:00Z","attendees":["sam@example.com"]}
   ```

   **Approval needed** for `create_event`: **Allow once**. Then send
   `/tool mcp:calendar.send_invite {"eventId":"<id from the reply>"}`: sending is asked every
   time, with its own card. **Allow once**: the invite is sent. Settings → **Diagnostics** →
   audit shows both decisions.
7. **A rule.** **Rules** tab → **New rule**: "Ask before sending invites", effect **Ask**, tools
   `mcp:calendar.send_invite`. The preview lists the call from step 6 it would have matched.
8. **Woken by an event.** Settings → **Triggers** → **New trigger**: MCP event, server
   `calendar`, event `invite.received`, wakes Scout. Run
   `curl -X POST localhost:$(jq .port /tmp/nova-cal.json)/emit -d '{"event":"invite.received"}'`:
   the delivery shows **started** and Scout's thread has a new turn. The same delivery id again is
   **duplicate**; an unsigned one is refused (401).
9. **A wake it sets itself.** Send `/tool schedule.wake {"at":"<in an hour>","reason":"Check the
   review notes"}`. Work → **Scheduled** lists it as "Set by Scout" with the reason; **Delete**
   removes it.
10. **Slack (optional).** Settings → **Channels** → **Add channel**: a Slack DM (private) and a
    shared channel for Scout, the mock's tokens. A detail told in the DM is not repeated in the
    shared channel: the owner gets "Share a private detail?" and **Do not share** keeps it out.
11. **The browser (optional).** Settings → **Browser**: allow `127.0.0.1` by name and turn on
    local sites; serve `packages/core/test/fixtures/site/` on a local port. Send
    `/tool browser.navigate {"url":"http://127.0.0.1:<port>/"}` then `/tool browser.read {}`:
    the computer page's browser panel shows the page and the action trace with screenshots. A link
    to an unlisted host is blocked with the reason; a page saying "ignore your instructions" is
    flagged and its button asks every time.
12. **Take over.** Scout's computer page → **Computer use** on → **Take over**: the live view
    takes your clicks and keys and the control indicator shows. **Return control**; the kill key
    (Esc) stops control at once and pauses Scout until you resume.

## Expected results
- Research reads only the declared tool; `create_event` and `send_invite` each ask; the rule's
  preview matches; the signed event wakes Scout once; the wake shows as set by Scout.
- Nothing private reaches the shared channel without your decision.
- The browser stays on allowed sites; every action is in the trace with screenshots.
- Takeover and the kill key are audited; the audit chain verifies.
