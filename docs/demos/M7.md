# M7 — Demo

A phone starts a task through the Relay and the desktop approves it; before that, two browsers
keep an offline copy of the Hub and stay in step, both change the same page offline (the later
change wins, and the other comes back from the merge log), changes made offline go out in order,
and a Code session on a cloud environment finishes on the runner while the laptop is closed.
Everything runs offline on the Mock provider, with the self-hostable cloud runner
(`services/runner`) and Relay (`services/relay`) on this machine.

## Preconditions
- `npm ci && npm run build`; a fresh data directory. The Mock provider answers "You said: …" and
  calls the tools named on lines like `/tool exec.run {"cmd":"./build.sh"}`.
- Linux with bubblewrap working for your user (not root): the runner's sandbox.
- Four Chromium windows with their own profiles, all at `http://127.0.0.1:7419` (loopback is a
  secure context, so devices join over plain HTTP): the owner's desktop, "Laptop A", "Tablet B"
  and a phone (`chromium --user-data-dir=$(mktemp -d)` for each; the phone with DevTools' device
  toolbar set to a phone). A real phone needs the Hub on HTTPS (Network → Trust → Hub local CA,
  with the root installed on the phone).
- To take a window offline: DevTools → Network → **Offline**; back: **No throttling**.
- A repository for the runner, in a folder the runner may clone `file://` repositories from:

  ```sh
  mkdir -p /tmp/nova-repos/calc && cd /tmp/nova-repos/calc && git init -q -b main
  printf '#!/bin/sh\nsleep 20\necho "built on the runner"\n' > build.sh && chmod +x build.sh
  git add -A && git commit -qm 'Initial commit'
  ```

## Script
1. `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`, open the setup link in the owner's
   window, **Finish setup**, **Skip setup**.
2. **Two devices with an offline copy.** Sidebar → **Devices** → **Add device** → **Client**, tick
   **Offline copy**, **Create code**. Open the link under "Or send the device this link" in Laptop
   A's window: name it "Laptop A", **Ask to join**; it shows six digits. On the owner's window,
   "Laptop A wants to join": type the digits, **Approve**; Laptop A shows "This device is added",
   **Open Nova**. Do the same for "Tablet B". On each device, Settings → **Sync** → "This device"
   says **Up to date** and "encrypted on this device"; the owner's window says this browser keeps
   no copy and lists both devices' copies as synced.
3. **An edit on one appears on the other.** Leave Tablet B on Settings → Sync. On Laptop A,
   **New chat**, send "Trip planning" (the Mock answers "You said: Trip planning"). B's "This
   device" turns to "1 chat, 2 messages" without a reload, and the chat shows in B's sidebar; open
   it there.
4. **A forced conflict.** On Laptop A, Sidebar → **Spaces** → **New space** "Trip" → **New page**
   "Packing list", text "Passport", **Save**. Once B's Settings → Sync counts "1 space, 1 page",
   open the same page on Tablet B. Take both windows offline. On A change the text to "Passport,
   tickets" and **Save**; then on B to "Passport, charger" and **Save**. Each says "Offline: showing
   what this device has." and the change waits to send. Bring A back online; once its change is on
   the Hub, bring B back: B's change is the later one and wins on the Hub and on A. On A, Settings →
   Sync → **History**: "Page “Packing list” · Content", "Changed in two places at about the same
   time", with both values and who set them. **Restore the replaced value** → **Restore**:
   "Passport, tickets" is back on the Hub and on both devices (B's open editor follows live).
5. **Changes made offline go out in order.** Open "Trip planning" on Laptop A and take A offline.
   Send "First stop: Lisbon", "Second stop: Porto" and "Third stop: Faro" (the chat shows them as
   "Queued: 3"), then rename the chat (**Actions for Trip planning** → **Rename**) to "Lisbon
   trip". Settings → Sync → "Changes waiting to send" lists the four in that order, each **Waiting
   to send** (the page edit of step 4 shows as sent until **Clear sent**). Bring A back online:
   they turn **Sent** in order, the third message saying "Sent. The Hub is answering it now." Back
   in the chat nothing is queued any more: the three messages are labelled "Written offline",
   followed by the Mock's answer to the last. Optional: rename, offline, a chat the owner deletes
   meanwhile; on reconnect it shows **Not sent**, "It was deleted on the Hub.", and **Discard**
   removes it after asking.
6. **A cloud run while the laptop is closed.** Start the runner:

   ```sh
   node services/runner/src/main.ts token add --data-dir /tmp/nova-runner --label demo   # prints nvrun_…
   node services/runner/src/main.ts --data-dir /tmp/nova-runner --port 7431 --local-repos /tmp/nova-repos
   ```

   In the owner's window, Settings → **Cloud runner**: Runner address `http://127.0.0.1:7431`
   (plain HTTP only for this machine), Runner token, **Save**; turn on **Use the cloud runner** (it
   asks first, naming the address) → **Turn on**: **Ready**. **New cloud environment**: name
   "Calc (cloud)", **Repositories** `file:///tmp/nova-repos/calc`, setup script
   `test -x /workspace/calc/build.sh && echo ready`, **Create environment**; it turns **Ready**
   (it has no network: the form offers none unless the owner allows unrestricted runner network).
   Sidebar → **Code** → **New session**: environment "Calc (cloud)", folder `/workspace/calc`,
   title "Cloud build", **Start session**. Send `/tool exec.run {"cmd":"./build.sh"}`; on
   **Approval needed**, **Allow once**, then close the tab at once (the laptop goes away). After
   half a minute open the Hub again → Code → "Cloud build": the reply shows "built on the runner",
   and "Cloud run on Calc (cloud)" counts 1 command; **Open the run’s page** shows its usage against
   the caps.
7. **The phone starts a task through the Relay; the desktop approves it.** Start the Relay
   (`node services/relay/src/main.ts --host 127.0.0.1 --port 7430 --data-dir $(mktemp -d)`); in
   Sidebar → **Network** → **Relay** turn on **Use a Relay**, address `ws://127.0.0.1:7430`,
   **Save** → **Connect**: **Connected**. In the phone's window block the Hub's API first
   (DevTools → Network request blocking, pattern `*127.0.0.1:7419/api/*`), so everything it does
   has to go through the Relay; the page itself still loads. Add the phone as in step 2
   (**Client**, no scopes, named "Pixel phone") with "How it connects" → **Through the Relay**: its
   join page pairs through the Relay, and once approved its account menu says it is connected
   through the Relay (the Hub's Content-Security-Policy now names the Relay, and the Relay
   answers the page's cross-origin requests). On the phone: the
   account menu → **Approvals** ("Nothing is waiting for you") → **New task**, **Work run**, and as
   "What should it do?":

   ```
   Make the packing list for the trip.
   /tool artifact.create {"kind":"markdown","title":"Packing list","content":"# Packing list\n\n- Passport\n- Charger"}
   /tool run.complete {"summary":"Packing list saved for the trip."}
   ```

   **Start**: the phone opens the run. On the owner's desktop, Sidebar → **Approvals**: "1 approval
   is waiting." with the `artifact.create` card; **Allow once** ("All answered."). The phone's run
   shows the result live: "Packing list saved for the trip." and the "Packing list" artifact's
   card (its content is fetched by address, which the tunnel does not carry yet). Network → Relay
   lists "Pixel phone" among the paired clients, **Active**.
8. **Revoke.** Devices → Tablet B → **Revoke** (it asks first). B's session ends at once; the page
   removes its offline copy and its key, and says why.
9. **Hand off a Code session (optional).** Two clones, the first with a commit the second lacks:

   ```sh
   git clone -q /tmp/nova-repos/calc /tmp/calc-on-a && git clone -q /tmp/nova-repos/calc /tmp/calc-on-b
   cd /tmp/calc-on-a && git checkout -q -b trip-totals && echo 'Totals per trip.' > NOTES.md
   git add NOTES.md && git commit -qm 'Notes for trip totals'
   ```

   Code → **New session**: folder `/tmp/calc-on-a`, permission mode **Accept edits**. Send
   `/tool fs.write {"path":"build.sh","content":"#!/bin/sh\necho total\n"}` (an uncommitted change).
   **Hand off…** → **Another environment**, "This Hub", repository folder `/tmp/calc-on-b`, **Keep
   them here too** → **Move session**: "Session moved", "It continues in /tmp/calc-on-b.", with the
   branch, the commit and 1 changed file. The clone is on `trip-totals` at that commit with the
   change uncommitted; the source keeps its change; the **Moves** tab lists the move.

## Expected results
- A device keeps an offline copy only while it has the Offline copy scope; the copy is sealed on
  the device, and revoking the device removes it.
- An edit on one device reaches the other's copy without a reload. When two devices change the
  same field, the later change (hybrid logical clock) wins everywhere; the other is in Settings →
  Sync → History with who set it, and Restore puts it back as a new change.
- Changes made offline show their status, reach the Hub once and in order, and a refused one says
  why and stays until it is retried or discarded.
- The cloud command runs on the runner, in its sandbox and without network, while the laptop is
  away; the run counts its commands and time against its caps.
- The phone's task waits for the desktop's answer, the first answer from any device counts, and
  the phone sees the result live; through the Relay, which sees only sealed envelopes.
- Every device add and revoke, restore, runner change, cloud run, approval and handoff is in the
  audit log.
