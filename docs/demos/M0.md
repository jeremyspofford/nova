# M0 — Demo

## Preconditions
- Node 24 or later; dependencies installed with `npm ci`.
- A clean data directory (the demo uses a temporary one).

## Script
1. Build the web UI: `npm run build`.
2. Start the Hub with a fresh data directory:
   `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`.
   The console prints `Open this link to set up Nova (valid 1 hour)` and a URL ending in
   `#setup=nvs_…`.
3. Open the link. The page says "Setup link detected". Enter a name and choose **Finish setup**.
4. The shell greets you by name. The setup code is gone from the address bar.
5. Press `Ctrl+K` (`⌘K` on macOS). The command palette opens and says "No commands yet". Press
   `Esc` to close it.
6. Choose the **Theme** button twice. The page switches from the system theme to Light, then
   Dark. Reload: the choice is kept (it is stored on the Hub).
7. In another terminal, `curl -i http://127.0.0.1:7419/api/v1/settings` returns `401` with
   `token_required`.

## Expected results
- The Hub serves the UI and the API from one port; requests without a session are refused.
- The first-run setup code works once and only once.
- Migrations ran on first start (`schema_migrations` holds version 1).

## Evidence
- `npm run lint && npm run typecheck && npm test && npm run build` (all green).
- `scripts/e2e-docker.sh` (or `npm run test:e2e` on a host with Chromium's libraries): the M0
  smoke journey passes.
- `node scripts/cargo.mjs test`: the `novad` skeleton's tests pass, and its capability document
  validates against `contracts/schemas/device-capability.json`.
