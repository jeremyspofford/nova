# M3 — Demo

Ask for a file summary; watch a read tool run without asking and a write tool ask first
(`docs/17` M3).

## Preconditions
- `npm ci && npm run build`; a fresh data directory. No network or model is needed: the
  offline Mock provider drives tool calls from lines like `/tool fs.read {"path":"notes.txt"}`.
  A real model calls the same tools on its own.
- Optional: Docker or Podman, so exec tools can run in a container sandbox (without one they
  are refused with a clear message, never run unsandboxed).

## Script
1. `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`, open the setup link, **Finish setup**,
   **Skip setup**. Put a file in `$NOVA_DATA_DIR/workspace/notes.txt` (the Hub's workspace folder;
   Settings → Permissions adds more folders).
2. New chat: `/tool fs.read {"path":"notes.txt"}` — the read runs at once and its tool card shows
   the result; the reply quotes it.
3. `/tool fs.write {"path":"summary.md","content":"…"}` — an approval card appears with the
   action, the reason, whether you asked for it and the options. **Allow once** writes the file;
   the same call asks again; **Allow for this session** stops the asking in this chat only.
4. `/tool exec.run {"cmd":"npm test"}` → **Always allow…**: the narrowest scope, "Commands
   starting with npm test", is preselected and becomes a command rule listed in Settings →
   Permissions; `npm test && curl …` still asks. Try **Deny and continue** with a reason (the
   agent receives it), **Deny and stop**, and **Hand off** (the chat shows Needs input until
   **Mark done**).
5. Settings → Tools & MCP → **Add server**: command `node`, arguments
   `packages/mcp/test/fixtures/test-server.mjs` (absolute path) — it shows Connected, with its
   tools, logs and a per-tool default. `/tool mcp:test.purchase_item {"item":"book","priceUsd":12}`
   asks with no session or "always" option, even if a file in the conversation says it is
   approved.
6. The bell in the top bar lists the approval notifications. Inspector → Activity shows the
   turn's tool calls and decisions. Settings → Diagnostics shows the Hub's health, logs and the
   audit log; **Verify integrity** checks the hash chain.
7. Settings → Memory: **Consolidate now** writes a summary from idle chats; **Remember more /
   less** per category; **Reference past chats** on or off.

## Expected results
- Read tools run without asking; writes, commands, MCP tools and purchases ask, each with the
  options its tier allows; denials and hand-offs behave as documented in docs/12 §4.
- Every decision is in the audit log and the chain verifies.
- No serious or critical accessibility violations on the chat, Tools & MCP and Permissions
  screens.
