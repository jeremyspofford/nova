# M6.5 — Demo

Add a headless computer with the one-line command and a phone with a QR code, both approved on
the Hub by typing the code the device shows; then turn the LAN off and watch the Relay become the
path the Hub advertises. Everything runs offline: the Relay is the self-hostable one from
`services/relay` on this machine, and the mesh steps use the fake mesh tools from the tests.

## Preconditions
- `npm ci && npm run build`; a fresh data directory.
- A `novad` build in a dist folder: `node scripts/cargo.mjs build --release`, then
  `mkdir -p /tmp/nova-dist && cp services/novad/target/release/novad /tmp/nova-dist/novad-linux-amd64`
  (`arm64` on an ARM machine).
- Optional, for the mesh steps: a tools file pointing the mesh CLIs at the fake
  (`packages/core/test/fixtures/mesh/fake-mesh.mjs`), as `e2e/j8-5-add-device.spec.ts` writes it.
- Open the Hub at this machine's LAN address (for example `http://192.168.1.20:7419`), not
  `localhost`: the Hub does not build an install command for a loopback address another machine
  cannot reach.

## Script
1. `NOVA_HOST=0.0.0.0 NOVA_NOVAD_DIST=/tmp/nova-dist NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`,
   open the setup link at the LAN address, **Finish setup**, **Skip setup**.
2. **A headless computer.** Sidebar → **Devices** → **Add a device** → **Compute node** →
   **Create code**. The page shows a QR code, the short code (`ABCD-EFGH`, valid 5 minutes, one
   use), a countdown and, under "On a computer without a screen", the one-line command: it
   downloads the build for the machine's architecture, checks its SHA-256, and runs
   `novad install` with the pairing id and the Hub's fingerprint (`--pin`).
3. Run the command on the other computer (or run `novad install … --no-service` here). It prints
   `Hub identity verified`, `Signed build manifest verified`, then
   `Confirm this code on the Hub: 123 456`. The Hub shows "<name> wants to join": type the six
   digits the computer shows and **Approve** (a wrong code is refused). The computer registers;
   its page shows it online with its capabilities. Running the same command again fails: the
   code is spent.
4. **A phone.** **Add a device** → **Client** → **Create code**; scan the QR code with the phone
   (or open the join link). The join page checks it is talking to this Hub (the fingerprint in the
   QR), then shows six digits. Nothing on the Hub is reachable from the phone yet. Type the digits
   on the Hub and **Approve**: the phone shows **Open Nova** and how to install the app (Add to Home
   Screen on iOS, the install prompt elsewhere). On the phone's device page, **Revoke** ends its
   session at once.
5. **The Relay.** On this machine: `node services/relay/src/main.ts --host 127.0.0.1 --port 7430
   --data-dir $(mktemp -d)`. Sidebar → **Network** → **Relay**: turn it on with
   `ws://127.0.0.1:7430` (plain `ws://` is allowed for loopback only). The state turns
   **Connected**; **Overview** lists the Relay endpoint next to the LAN ones.
6. **Turn the LAN off.** Network → **Overview** → the network settings: turn **LAN** off and save.
   The transport log says the LAN is no longer advertised and the Relay is now primary; a client
   that cannot reach the LAN pairs and talks to the Hub through the Relay (J8.5 step 4 drives one).
   **Roll back the last change** turns the LAN back on.
7. **Network setup (optional, fake mesh).** Network → **Setup**: turn on host changes (it asks
   first), choose Headscale with Tailscale, plan, and apply each step with its consent. The step
   that brings the mesh up fails its reachability test (the fake mesh address does not answer) and
   is rolled back by itself; the mesh endpoint is never advertised.
8. **Trust.** Network → **Trust**: choose **Hub local CA**, restart the Hub; it serves HTTPS with
   the CA's certificate. Download the root (`ca.crt`) on a device to trust it.

## Expected results
- Joining always takes the owner's approval with the code the device shows; a code works once and
  for 5 minutes; a revoked device loses its session at once and its key cannot join again.
- `novad install` refuses a Hub whose identity does not match the pin, a manifest the Hub did not
  sign, and a binary that is not the signed build, before it writes anything.
- Only endpoints that pass their own reachability test are advertised; the transport log records
  every change of primary path; a failed setup step is rolled back.
- Every add, approval, revocation, transport, trust and network change is in the audit log.
