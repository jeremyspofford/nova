# M5 — Demo

Delegate a Work run, pause it at a budget and extend it, fire a schedule, escalate from a chat,
then review and commit a Code session on a local repository. Everything runs offline on the Mock
provider. `docs/17` names a PR and CI for the evening demo; the PR flow is not in M5 (ADR-092),
so the Code part ends with a commit on a `nova/` branch.

## Preconditions
- `npm ci && npm run build`; a fresh data directory. No network or model is needed: the offline
  Mock provider calls the tools named on lines like `/tool plan.set {"steps":[…]}` (all of a
  message's lines in one step) and answers other messages with "You said: …".
- Git on the Hub's machine. A small repository outside the home folder:

  ```bash
  mkdir -p /tmp/nova-demo-repo && cd /tmp/nova-demo-repo && git init -q -b main
  git config user.name "Demo" && git config user.email demo@example.com
  printf 'one\n' > notes.md
  printf 'export const add = (a, b) => a + b;\n' > math.js
  git add . && git commit -qm init
  ```
- Optional: Docker or Podman with an image named in `NOVA_SANDBOX_IMAGE` (as in M4). Without
  one, the "This Hub" environment is degraded: edits, diffs, reviews and commits still work, but
  the Terminal tab and `test.run` say the Hub has no sandbox.

## Script
1. `NOVA_DATA_DIR=$(mktemp -d) node apps/hub/src/main.ts`, open the setup link, **Finish setup**,
   **Skip setup**.
2. **A Work run with a plan, an approval and an artifact.** Work → **New run** (or the palette's
   **New run**, or `/work?new=1`). Objective, three lines:

   ```
   /tool plan.set {"steps":[{"title":"Write the status note"},{"title":"Report the result"}]}
   /tool artifact.create {"kind":"markdown","title":"Status note","content":"# Status\n\nAll green."}
   /tool run.complete {"summary":"Saved the status note."}
   ```

   Keep Standard autonomy and the default budgets, **Start run**. The run page shows the plan card
   with both steps, and the run's conversation shows **Approval needed** for `artifact.create`;
   the run and its sidebar row say **Needs input**. Press Ctrl/Cmd+Alt+A from another page: it
   jumps back to the run. **Allow once**: the run ends **Done**, and the result card shows "Saved
   the status note." with a preview of the Status note. Open **Activity**, step through it and
   replay it; nothing runs again.
3. **A budget pause and an extension.** **New run** again. Objective: the line `/tool fs.list {}`,
   then on the next lines any text of about 4,000 characters (the Mock counts one token per four
   characters). Set **Tokens** to 1000 and start it. The listing runs, and before the next model
   step the run pauses: the banner "Budget reached: tokens" (Blocked) shows the tokens used against
   the budget, a progress summary, **Extend 1M tokens** and **Extend budget…**. Nothing runs while
   it waits. **Extend 1M tokens** ("Added 1M tokens.") adds to the bound; the run continues and
   ends **Done**.
4. **A schedule fired now.** Work → **Scheduled** → **New schedule**: title "Morning hello", Daily
   at 09:00 in your time zone, instructions `Say hello`, results to In-app (the default), catch-up
   "Catch up once". **Save schedule**: the row shows the next run. **Run now**: a run "Started by
   a schedule" runs and finishes, the bell shows its message, and **History** lists the fire with
   outcome **Done**, verified by the in-app receipt (FR-187). **Pause** shows "Paused" in place
   of the next run; **Resume** brings it back without catching up the paused time.
5. **Escalation from a chat.** New chat:

   ```
   /tool work.start {"objective":"Collect this week's notes into a summary","title":"Weekly summary","plan":["Read the notes","Write the summary"]}
   ```

   The tool card becomes a run card: "This run was proposed in a chat. It starts when you accept
   it.", the two plan steps, the budget, **Start run** and **Dismiss**. The Work list shows the
   run as Needs input. **Start run**: the card shows live progress with **Stop**, then the
   summary (the Mock's reply) and **Open in Work**, which opens the run page "Started from a
   chat".
6. **A question from a run.** **New run** with the objective
   `/tool ask_user {"question":"Which format?","choices":["Markdown","PDF"]}`. The run's
   conversation shows a question card with **Markdown** and **PDF**; the run is Needs input.
   Choose **Markdown**: the card shows the answer and the run ends **Done**. The wait did not count
   against the run's time budget.
7. **A Code session.** Code → **New session** (or `/code?new=1`): "Folder path on the Hub"
   `/tmp/nova-demo-repo`, environment "This Hub", default model, mode Manual, **Start session**.
   In the session's composer, open the mode selector: Auto says it "needs a reviewer model in
   Settings → Code" and Bypass needs a VM or container environment; choose **Accept edits**.
   Send:

   ```
   /tool fs.write {"path":"math.js","content":"export const add = (a, b) => a + b;\nexport const sub = (a, b) => a - b;\n"}
   /tool fs.write {"path":"notes.md","content":"one\n[{\"path\":\"math.js\",\"line\":2,\"severity\":\"warn\",\"title\":\"sub has no test\",\"reasoning\":\"Add a test for sub.\",\"fix\":\"expect(sub(3, 1)).toBe(2);\"}]\n"}
   ```

   Both edits apply with no approval card (Accept edits). The **Diff (2)** tab lists `math.js` and
   `notes.md`, each `+1`, with the added lines marked + and read as "Added"; switch to **Split**
   and back.
8. **Review the diff.** On `math.js`, **Accept** its hunk; leave `notes.md` pending. Click line
   number 2 of `math.js`, type "Name it subtract?" and press Ctrl/Cmd+Enter: the comment goes to
   the agent as one message, and the Mock replies. Press **Review** in the header: the Review tab
   shows the **Code review** card with `math.js`, a **Warning** "sub has no test" and **Apply
   fix**, and the finding also shows in the diff. The Mock answers with the text it is sent, so
   its review is the JSON line written into `notes.md`; a real model writes its own findings.
9. **Commit on a `nova/` branch.** **Commit…**: message `Add sub`. The repository is on `main`,
   so the dialog suggests a new branch `nova/add-sub` and will not commit to `main`. Untick
   **Accept the pending changes and include them**, then commit. The dialog shows **Committed**
   with the sha and the branch (it also says the repository's hooks did not run; this repository
   has none). In a shell, `git -C /tmp/nova-demo-repo log --oneline -1 --stat`
   shows only `math.js`, and `git -C /tmp/nova-demo-repo status --short` still lists `notes.md`
   as modified: only accepted hunks were committed, and nothing was pushed.
10. **Optional, with a sandbox.** The **Terminal** tab opens a shell at the session folder; run
    `git branch --show-current` (prints `nova/add-sub`). Agent commands started with `exec.run`
    are listed there with an "agent" chip and **Kill**.

## Expected results
- A Work run records its plan, asks once for its consequential action, saves an artifact and
  ends Done with a result card; its Activity replays without side effects.
- A run that reaches its token budget pauses Blocked with a summary and waits; Extend adds to the
  bound and the run finishes.
- A schedule fired now starts a run, delivers in-app, and its history shows the fire as Done only
  because the delivery has a receipt.
- An escalated run waits for **Start run**, carries the user's authority only after it, and is
  listed under Work linked to its chat.
- A question waits as Needs input and its answer reaches the run.
- In Accept edits, file edits apply without a card and show as reviewable diffs; a commit takes
  only accepted hunks, goes to a new `nova/` branch, never to the default branch, and is never
  pushed. Nova's own Git calls run no repository hooks.
