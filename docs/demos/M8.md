# M8 — Demo

Switch Nova to a right-to-left language, then install a third-party theme and plugin from the
Marketplace and use them. Then show the three M8 exit criteria: a sample extension with a command,
a panel and a tool whose permissions are enforced; a managed policy that locks Bypass and the
network; and an export → delete → import round trip without data loss. Everything runs offline:
the Marketplace reads the built-in sample catalog from disk and the Mock model answers chats.

## Preconditions
- Linux; `npm ci && npm run build`; a fresh data directory.
- The sample extension packed: `node packages/cli/src/main.ts pack packages/sdk/examples/hello --unsigned --out /tmp/hello-1.0.0.novax`.
- For the policy part, a test policy file the Hub will trust (0600 in a 0700 folder, owned by the
  user the Hub runs as):

  ```sh
  P=/tmp/nova-demo-policy && mkdir -m 700 -p $P
  cat > $P/managed-settings.json <<'EOF'
  { "version": 1, "serial": 1,
    "restrict": { "permissionModes": { "deny": ["bypass"] },
                  "egress": { "mode": "allowlist", "allow": ["api.example.com"] } } }
  EOF
  chmod 600 $P/managed-settings.json
  ```

## Script
1. Start the Hub with the test policy (it is honoured only with `--allow-test-policy` or
   `NODE_ENV=test`, as a layer over the protected file):
   `NOVA_DATA_DIR=$(mktemp -d) NOVA_MANAGED_SETTINGS_FILE=$P/managed-settings.json node apps/hub/src/main.ts --allow-test-policy`.
   Open the setup link, **Finish setup**, **Skip setup**.
2. **Right to left.** Settings → **Appearance** → Language → **العربية (partly translated)**. The
   page turns right to left, the sidebar moves to the right and its labels are in Arabic. Choose
   **English** to come back (languages are listed by their own names).
3. **A third-party theme.** Sidebar → **Marketplace** → **Themes**: **Aurora** by Example Labs,
   **Verified**. **Install Aurora** → the dialog shows it Verified and its colors, with no sideload
   box → **Install**. Settings → **Appearance** → Your themes → **Use Aurora**: the page turns
   deep blue with a mint accent.
4. **A third-party plugin.** Marketplace → **Plugins** → **Release notes**, **Verified** → **Install**.
   In a new chat type `/chan`, pick **/changelog-entry**, add `2.1.0`, Enter: the reply carries the
   plugin's instructions ("The user loaded this skill with /changelog-entry.").
5. **An extension, its permissions enforced.** Settings → **Extensions** → **Choose a .novax file** →
   `/tmp/hello-1.0.0.novax`. The preview says "This extension is not verified" and lists what it
   can do (reach api.example.com, its own data folder, the secret "greeting", the tools greet,
   save_note and check_status). Tick **I trust its source; install it unverified** → **Install**:
   **Running**, "1 command, 1 panel, 3 tools, …".
   - **Commands** (top bar) → "say hello" → **Hello: say hello**: a toast, and the status bar says
     "Hello: 1".
   - On its card → **Open Hello**: the panel "Hello from an extension", served from its own files.
   - In a chat: `/tool ext:com.example.hello/greet {"name":"Ada"}` → "Hello, Ada!".
     `/tool ext:com.example.hello/save_note {"text":"Remember the tea."}` asks first → **Allow once**
     → "Saved." (in its own data folder).
   - `/tool ext:com.example.hello/check_status {"host":"status.example.net"}`: refused before any
     request leaves the Hub ("… asked for the host status.example.net, which it did not declare").
     The extension is turned off and a notification "Extension com.example.hello was turned off"
     leads back to Settings → Extensions; Settings → Diagnostics → Export audit log has
     `extension.access.denied`. Turning it off removes its command from the palette and its tools
     from the model; turning it on brings them back.
6. **Managed policy.** Settings → **Managed policy**: "Test policy file", **In force**, the file's
   path, "These modes are turned off: Bypass.", "Agents may reach hosts only within:
   api.example.com." and "Hosts agents may reach now: api.example.com." Settings → **Code**: "Allow
   Bypass mode" is off and disabled, "Managed by your organization (test policy file)".
   **Permissions** ("When to ask") and **Network** ("Network access") are locked, each with "Managed
   by your organization (test policy file)". Network shows "Sandboxes may reach now:
   api.example.com.": the policy's list is a ceiling over your own allowed hosts, which you can
   still edit within it. Edit the file to `"egress": {"mode": "off"}` and add
   `"unverifiedInstalls": false`, then Managed policy → **Check for changes**: "Agents have no network
   access.", Network shows **Off** (locked), and the unverified Hello extension is **Stopped**.
7. **Export, delete, import.** Restart the Hub without the policy (step 1 without the two policy
   parts). Settings → **Data** → Export without a passphrase (the extension's secret is left out and
   listed to re-enter), then with one (twice, plus the Hub's name): an encrypted file. **Delete all
   data…** → type the Hub's name → **Delete everything and restart**. The Hub restarts and the page comes
   back on Settings → **Data**. Under Import (on a brand-new Hub, onboarding's **Restore from an
   export file** leads here) → choose the encrypted file → passphrase → **Check the file** →
   **Import…** → **Import and restart**: "The import is done and verified.", "1 plugin was turned off."
   The chats, projects, memory and the extension (with its secret stored) are back; turn the
   extension on again.

## Expected results
- A right-to-left language mirrors the shell; languages are always listed by their own names.
- Marketplace items from the signed sample catalog install Verified with no sideload step; the
  theme applies token for token and the plugin's command works in a chat.
- An extension does only what its extension.json declares: anything else is refused before it
  happens, audited, and the extension is turned off with a notice; off means its command and tools
  are gone.
- A managed policy locks what it sets and says so with its source on each control. Its allow list
  is a ceiling: the hosts in force are shown on Network and Managed policy. The Hub refuses locked
  changes as `managed`, and a stricter policy read again applies at once.
- An export → delete → import round trip brings back every table and file (`verified: true`); what
  an archive cannot vouch for (plugins, stdio MCP servers, hooks, other sessions) comes back off.
