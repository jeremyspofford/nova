# UI review — 2026-10-06

A full styling/layout review of the v4 web app (`apps/web`) as deployed on
:3000, on desktop (1440×900), tablet (820×1180) and phone (390×844), dark
mode, default **Nova** theme. 18 routes × 3 widths = 142 screenshots plus a
mechanical DOM audit (off-screen content, inner horizontal scroll, clipped
text, fonts under 12px, phone tap targets under 32px). Every finding below
was checked against a screenshot and pinned to source.

Evidence (gitignored, durable): `.worktrees/ui-review-2026-10-06/shots/`
named `<viewport>__<route>__<scrollstep>.png`, the audit in
`shots/report.json`, and the rig `shot.mjs` (playwright image, session
minted for the owner — see "Method" at the end). Paths below are relative to
`apps/web/src` unless they start with `apps/`.

Nothing has been changed. This is the list.

## Part 1 — Root causes that break many pages at once

Fixing these first removes roughly half of everything in Part 2.

### R1. Phone: the menu button sits on every page title — **high**
The floating hamburger covers the H1 on every non-chat page at phone width
(Settings, Inbox, Activity, Schedules, Agents, Skills, Files, Spend, AI
Quality, Governance), and covers the first message on Chat. The 3rem reserve
meant for it never applies.

- Cause: `components/layout/AppLayout.tsx:100` and `:109` put **two**
  arbitrary `pt-[…]` classes on `<main>` at once —
  `pt-[var(--nova-safe-top,0px)]` always, plus
  `pt-[calc(var(--nova-safe-top,0px)+3rem)]` when mobile. Tailwind emits
  them in its own order; in the deployed CSS the 0px rule comes **after** the
  3rem rule, so 0px wins. Verified in the built stylesheet, not a stale build.
- Also: the button (`MobileNav.tsx:149-155`, `fixed left-3 z-[60]`) has no
  background, so scrolled content (card borders, section icons, "By model")
  slides visibly underneath it.
- Fix: emit one class (`isMobile ? 'pt-[calc(...)+3rem]' : 'pt-[var(...)] md:pt-0'`)
  and give the button a `bg-surface-root/90 backdrop-blur` chip or a slim
  sticky top bar.

### R2. Words run together everywhere — **high**
All sans text reads as run-ons: "howdoigetyouonmyphone", "AIQuality",
"Runnow", "7dago", "1nolonger exists", "Howthisinstancelooks…".

- Cause: the default face Plus Jakarta Sans Variable (`lib/fonts.ts:32`,
  `DEFAULT_FONT='jakarta'`) has a very narrow space glyph — measured 3px at
  16px (≈0.19em) — and nothing compensates (no `word-spacing` anywhere).
- Caveat: measured in headless Chromium; confirm on the phone and a desktop
  browser before fixing.
- Fix: `word-spacing: 0.06–0.08em` on `body` for the Jakarta stack, or make
  Inter the default face.

### R3. Tablet gets the desktop shell with a 240px sidebar — **high**
At 820px the full sidebar stays open, leaving ~530–580px for content, while
every page's `sm:`/`md:` breakpoints (keyed on the *viewport*) think there is
room for multi-column layouts. This one cause produces most tablet breakage:
tables overflowing (Schedules −456px, Agents, Activity, Models −250px),
Spend's 4 stat tiles wrapping "$0.66 / $25.00" onto 3 lines, Inbox titles
broken into one fragment per line, Models' description squeezed to 180px.

- Cause: `hooks/useIsMobile.ts` switches at 768; `AppLayout.tsx` defaults the
  sidebar expanded.
- Fix: collapse the sidebar (or use the drawer) below `lg` (1024). Longer
  term: switch layouts on *content* width (container queries) rather than
  viewport.

### R4. Tables are unusable on phone (and on tablet) — **high**
Every data table scrolls sideways inside its card with no hint, hiding the
columns that matter:

| Page | Overflow at phone | What is hidden |
|---|---|---|
| Schedules | 645px | Runs as, Next fire, Status, Last outcome, Pause/Run now/Delete |
| Agents | 278px | Spent, Last active, Tools |
| Agent → Traces | ~280px | Model, Status, Duration, Tools |
| Activity | 288px | **Status (incl. red errors)**, Duration, Tools |
| Files | 191px | Size, Modified (plus the path runs into the card edge) |
| Governance | 157px | Actor clipped to "eval ha" |
| Models (tablet) | 250px | Price and all action icons |

- Cause: five hand-rolled `<table>`s (`SchedulesPage.tsx:520`,
  `AgentsPage.tsx:216`, `FilesPage.tsx:154`, `AgentPage.tsx:466`,
  `activity/ActivityTable.tsx:111`, `GovernancePage.tsx:121`) instead of
  `components/ui/Table.tsx`; nowrap cells; unbreakable mono paths.
- Fix: move them onto `Table`, give `Table` a stacked/card rendering below
  `md` (Models already has a phone card list — generalise it), and hide
  low-value columns below `lg` (`hidden lg:table-cell`).
- Related: **sticky table headers never stick** (Schedules, Agents, Activity,
  Governance, and `Table.tsx:46/55` itself) — the `overflow-x-auto` wrapper
  becomes the sticky container and never scrolls vertically, so headers
  scroll away on long lists.

### R5. `border-line` is not a colour — bright white borders — **high**
Spend's provider cap cards, Settings → Routing role cards, Settings →
Providers cards and some Models chips draw hard near-white 1px outlines that
match nothing else.

- Cause: `border-line` is used in SpendPage (239, 255, 262), ModelsPage (568,
  873), RoutingSection (670), ProvidersSection (365, 632, 826), CompareView,
  ModelDetails, BenchmarkCharts, PullControl — but `tailwind.config.js`
  defines only `border.{DEFAULT,subtle,focus}`, so it falls back to the
  preflight default.
- Same class of bug: `bg-surface-raised` (Inbox tabs, `InboxPage.tsx:234`) and
  `hover:border-border-strong` (`AppearanceSection.tsx:331`) are also
  undefined tokens and render nothing.
- Fix: `border-border`; and add a test that every `border-*/bg-*/text-*`
  token used in `src/` exists in the config (mechanical, not a review).

### R6. In dark mode, borders and tracks are invisible — **high**
`--border-default` is neutral-800 in dark (`index.css:112-121`) — the same
as `--surface-elevated` and next to card/input. Consequences:

- unchecked checkboxes and unselected radios are nearly invisible (only the
  selected radio of "Local only / Local first / Cloud only" shows);
  `Checkbox.tsx:63`, `Radio.tsx:49`; off-toggle tracks are faint;
- Secondary, Outline and Ghost buttons look identical (plain text) —
  `Button.tsx:11-18`;
- ProgressBar tracks vanish (`ProgressBar.tsx:24`), pending PipelineStages
  segments vanish;
- **chat code blocks** are `dark:bg-neutral-950` on a neutral-950 page —
  commands read as stray mono text with no box (`Markdown.tsx:251`).
- Fix: a stronger control-border step in dark (neutral-700/600), a distinct
  secondary fill, `bg-surface-elevated border` for `pre`.

### R7. `Input` ignores width classes — **med**
`<Input className="w-28">` sizes the inner `<input>` but the component wraps
it in `<div className="w-full">` (`components/ui/Input.tsx:17,36`), so every
short field stretches the whole card: Spend's monthly cap (~1120px for "25"),
Spend's Prices form, Behaviour's digest time and max-per-day (~1110px for
"20"), and the Routing "add a fallback…" select which pushes a lone "Add"
button onto its own line, six times.
- Fix: a `wrapperClassName` (or width on the wrapper), then use it.

### R8. The type scale is too small and too flat — **med**
11px (`text-micro`, `text-mono-sm`, Badge `sm`) carries real data on every
page: timestamps, badges, Inbox facts, Activity's Time column, Governance
times, chat inline code, the per-message model footer, the "SYSTEM" nav
label. In tertiary grey on dark it is at the edge of legible. Section titles
are 13px, the same as body text, so hierarchy is flat. Rows mix 11px sans
timestamps next to 12–13px mono values (Files, Agents, Activity).
- Fix: 12px floor for anything informational (`micro` → labels only);
  Section titles to `text-h4`; timestamps `text-caption`.

### R9. Phone tap targets — **med**
Button `size="sm"` is `h-7` (28px) and is the default for almost every page
action (Refresh, New agent, Edit/Delete, Pause/Run now, Mark seen, Load more,
Sign out…). Inline caption links are 15–20px tall ("All agents", "Change",
Behaviour's Inbox/Schedules links). Chat: Clear 30×22, context gauge 36×18,
model chip 22px, code copy button 22×22. Models' phone cards: four
unlabelled 33×28 icon buttons with hover-only tooltips.
- Fix: `h-9 md:h-7` for `sm` on touch; padded hit areas on inline links;
  text labels (or an overflow menu) instead of icon-only on touch.

### R10. Pages do not share one shell pattern — **med**
- Header: Chat has a 56px bar with a 16px title; every other page has a 24px
  H1 + description that scrolls away — the title jumps in size and position
  between pages.
- Padding: Models wraps itself in `p-4 md:p-6` inside the shell's
  `px-6 py-8` (`ModelsPage.tsx:721`) — its title sits 24px lower/right than
  every other page; the component gallery adds `p-10` (64px phone gutters).
- PageHeader always renders an empty actions `div` (+12px on phone,
  `PageHeader.tsx:20,27`); its description has no max width (1150px lines on
  Spend); and it switches to a row at `sm:` (viewport), squeezing text beside
  buttons on tablet.
- Hand-rolled copies: error/warning banners pasted in Spend, Quality,
  Governance; Inbox's own tab bar instead of `Tabs`; Spend's provider cards
  as bare divs instead of `Card`; Strengths chips instead of `Badge`; toggles
  in two sizes (Routing/Decisions `sm`, others `md`).
- Nested padding on phone: page `px-6` + Section `px-5` + card `px-4` leaves
  ~266px of a 390px screen inside Routing cards.

### R11. Navigation is incomplete — **med**
Spend and Activity are absent from the desktop sidebar; Activity is reached
from the account menu as "What she has done" while the page is titled
"Activity", and nothing is highlighted while you are on it (or on Spend /
Settings).

### R12. Raw machine text in the interface — **med**
- Inbox titles: ISO timestamps with microseconds
  (`2026-10-06T11:05:58.308491+00:00`), raw JSON error bodies, URLs cut
  mid-word.
- Models source badges carry full error strings ("could not reach
  http://100.122.40.93:8009/v1 — ConnectTim…"), wrapping into 2–6 rows of
  amber pills above the content.
- Spend "Recent refusals": 20 near-identical red lines of URL + ConnectTimeout.
- Routing "right now:" lines dump fallback chains and URLs; labels like
  "add to agent_file_helper".
- Skills summaries: quoted prompt fragments + repeated ISO dates, cut mid-word.
- Fix: format at the edge (relative time, "dell · unreachable", group by
  cause with a count), keep the raw text in a tooltip or disclosure.

## Suggested order

1. **R1** (one-line padding fix + button chip) and **R5** (undefined tokens,
   plus a test that refuses an undefined token) — small diffs, visible on
   every page.
2. **R2** word spacing — after confirming on a real device.
3. **R3** sidebar collapse below `lg` — fixes most of tablet in one place.
4. **R6** dark-mode borders/tracks/code blocks, **R7** Input width.
5. **R4** responsive `Table` with a stacked phone layout, then move the six
   hand-rolled tables onto it.
6. **R8/R9** type floor and touch sizes, **R10** shell consistency.
7. Part 2 page items; **R12** formatting at the edge.

Per the mechanical-over-prompts rule (CLAUDE.md), the durable versions of R5, R8 and R9 are
tests, not a style guide: an undefined-token check over `src/`, and the
existing playwright contrast audit (`tests/e2e/tests/10-theme-contrast.spec.ts`)
extended with the off-screen / tap-target / min-font checks from `shot.mjs`
at 390 and 820px.

## Method

- Session: minted an owner session in `nova-core-1`
  (`identity.create_session`) and set it as the `nova_session` cookie.
- Rig: `mcr.microsoft.com/playwright:v1.62.1-noble`, `--network host`,
  `node shot.mjs` with `ROUTES=...`; screenshots each route at the three
  widths, scrolling the largest scroll container in ~0.9-screen steps (the
  shell is `fixed inset-0`, so full-page screenshots don't work).
- Audit (in `shot.mjs`): elements extending past the viewport without a
  clipping ancestor, inner horizontal scroll, clipped/truncated leaf text,
  font size < 12px, phone tap targets < 32px. Leads, not findings — each was
  confirmed against a screenshot. Known false positives: `sr-only` inputs.
- Only dark mode with the Nova theme was reviewed; light mode and the other
  themes were not re-checked in this pass. The live data (69 inbox notices,
  an unreachable `dell`/`dell-kev`) shaped what was visible.
