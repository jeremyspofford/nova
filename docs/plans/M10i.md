## Design decisions

The desktop diagram gives the hub a clear leading position and connects other machines using manually drawn SVG lines. Machine controls use semantic HTML and readable text; the SVG must not duplicate screen-reader content. On a phone the same ordered machines become a quiet list. Like services and versions are rows with dividers, never equal-weight card grids. The title, group label and row title form the hierarchy. Colour carries one status per item; no decorative light or gradients are added.

Use neutral names such as Home hub, Study desktop and Travel notebook. The fixture is explicitly illustrative styleguide content. A cluster/heartbeat disagreement example demonstrates merged-health presentation without claiming a K3s backend exists. Default surfaces show only machine name, roles, one status and a short service/age summary. Reasons, versions and actions live in the next layer.

## Review Focus

- Long device/service names or roles: wrap without hiding status or horizontal scrolling (Task 1 browser assertions).
- Keyboard and touch navigation: every machine/service control has a name and visible focus; drill-in and back work (Task 1).
- Conflicting or stale observations: one overall status, both source reasons in detail, age explicit (Task 1 fixture assertions).
- Untrusted display strings: names/versions/reasons are escaped and cannot become markup or SVG attributes (Task 1 renderer assertion).
- Missing data or failed refresh: truthful empty, loading and error fixtures with at most one next step, no invented working system (Task 1).
