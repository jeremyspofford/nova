## The improvement loop's night, reconstructed

Goal 71973ec9 "Improve yourself, continuously" (approved 08-07 21:24, 20
actions, expires 08-10) launched 13 passes between 21:32 and 11:15 UTC.
Twelve died on OpenRouter HTTP 402; the one pass that ran (d755d720,
00:38–01:37) committed real work (ee57ed5d75 on `nova/db322bf5`) and then
died at the staging step because git-landing correctly refuses to land on a
host repo with ~7k uncommitted lines. Mechanics that made it expensive:

- **The hold was time-only and shorter than the tick.** `REFUSAL_COOLDOWN_S`
  = 3600s vs a ~90-min effective cadence, so the cooldown had always expired
  by the next tick: pass → 402 in ~15s → refund → cooldown → repeat, around
  the clock (active hours gate notifications, deliberately not work).
- **A dedupe collision burned one unrefundable action per cycle.** The refund
  decrements `actions_used`; the next charge reuses the same number; the
  dedupe key `improve:<goal>:<n>` collides with the already-decided card
  AFTER the action is charged, and that charge is never refunded. 8 actions
  lost this way; arithmetic: 21 charges − 8 refunds = 13 = actions_used.
- **Nothing preflighted the dirty repo.** Preflight said "ready" 13 times for
  passes that were all doomed at the staging step.
- **Each pass notified twice.** 24+ pushes/cards in one night about one
  unchanged wall; the heartbeat separately re-worded the same two findings
  into 14 fresh pushes because dedupe keyed on exact text.

What worked: the billing-wall hardening written mid-night (classify terminal,
refund, no blind retry, honest reason) behaved exactly as designed from 23:05
on; the heartbeat DID name the credit wall and the eval failures from 22:04.

## ROI decision

**Best ROI is not a build item: unblock the loop that is already built.**
Rails 1–5 of #47 exist and a standing goal is live; every pass verifiably
dies on (a) the exhausted OpenRouter key, (b) the coder's GitHub clone
missing the uncommitted tree, (c) a coder that cannot be told a token cap.
Three operator actions, near-zero code: top up / raise the key limit, mint a
SECOND spend-capped OpenRouter key into `CODER_API_KEY` (today it is a
byte-copy of the main key), and review+commit+push the working tree. Today's
fixes make the top-up safe to give: passes preflight the dirty repo before
charging, walls escalate instead of nag, and the coder is metered so the
$10/2M ceilings actually bind.

**Best build item, immediately after: #44 item 1 (sidecar auth) then #47
rail 6 (gated merge verb on git-landing + rollback watcher in
inference-control).** "Continuous, unapproved" is not true until merge and
rollback exist; sidecar auth is the non-negotiable prerequisite because an
unauthenticated git-landing with a merge verb is arbitrary-write-to-main.
Every gate input (sandbox verdict, different-model review, eval floor,
tripwire, backup freshness) already exists as code — this is assembly, ~3–5
days including the auth afternoon.

**Then #48 steps 1–3 (machine management).** "Do things on computers" is the
only priority with zero code; step 1 (her own workstation container: full
shell, package manager, Playwright+CDP browser) is the plan's own
highest-value-lowest-risk cut and also closes the improvement loop's weakest
gap (integration QA in a real browser).

Deliberately NOT next: #45 phase 2+ (heartbeat works and proved itself), #46
(shipped, needs marking), guests publish-half (blocked on the rate-limit
decision above), everything with no bearing on the four priorities.
