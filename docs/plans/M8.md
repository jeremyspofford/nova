# M8 plan: the Relay adapter

This plan covers roadmap item M8. The packet sources are:
- ROADMAP-AND-GATES M8;
- SYSTEM-MAP: Relay is a standalone worker service, integrated by adapter, and never rebuilt into Nova;
- ADR-8: vendor agents and worker services are adapters behind Nova's own contracts;
- CONTRACTS §1 (the task envelope);
- CAPABILITY-INVENTORY (Relay integration row);
- OPERATING-RULES, including local-only never falling back to cloud, not even with a warning.

The roadmap describes M8 in three parts:
- Relay is stabilized standalone first, in its own bounded pass: interface freeze, tests green, contracts documented.
- Nova then gets an adapter to Relay over the task envelope.
- **Gate:** a coding task briefed from Nova is executed by Relay workers in worktrees, and reported back with diff evidence.

**What we start from:** a survey of `jeremyspofford/relay` at `73d801c`, v0.8.0.
- `npm test` passes 144 of 144, and `npm run check` is green.
- `test:browser` fails 7 of 7 on this machine because Chromium's system libraries are missing. That's environmental, not a code fault.
- Relay is loopback-only, with no auth. Every POST and PATCH must carry the `X-Relay-Client: relay-local` header.
- Starting a worker takes five calls: connect project, create task, mark ready, pick profile, start worker.
- There is no per-run read. A caller has to pull the whole store or follow server-sent events.
- Only one run happens at a time.
- Claude is the only worker engine. Workers run in `<data>/worktrees/<runId>` on branch `relay/<runId>`. The diff comes back on the run record as `review.diff`.

**Hard limits:**
- No accounts and no spending.
- Relay is private and Nova is public, so Nova's CI can't fetch Relay. No deploy keys or tokens get created for it, because that would be a new credential.
- Nova's CI tests the adapter against a stand-in that follows Relay's written contract. The real Relay is exercised locally, through an opt-in test.
- No new CI for Relay. Relay is private, so Actions minutes could cost money. Relay's green tests are run locally and recorded in its PR.
- Real worker runs use Relay's fake worker CLI, or the local model through Ollama's Anthropic-compatible API. Both are free. No run uses the owner's Claude subscription without a fresh OK.

## 1. Relay stabilization (M8a): in the Relay repo, PR to its main

This work runs in a fresh clone, on branch `stabilize/contract-v1`. It does no redesign. The goal is to freeze what Nova uses and write it down. The version goes to 0.9.0.

1. **A per-run read.**
   - `GET /api/workers/:id` returns one worker run record: id, taskId, projectId, status, text (the handoff summary), usage, costUsd, worktree `{directory, branch, baseCommit}`, validation, review `{files, totalFiles, diff, truncated}`, error, createdAt and finishedAt. It answers 404 for an unknown id.
   - `GET /api/workers/:id/handoff.json` serves the handoff Relay already writes.
2. **Contract v1, written down.**
   - `docs/contract-v1.md` gives request and response shapes, statuses and error codes. It covers the routes an outside client uses: `GET /api/status`, `POST /api/projects`, `POST /api/tasks`, `PATCH /api/tasks/:id`, `GET /api/state` (profiles only), `POST /api/workers`, `GET /api/workers/:id`, `GET /api/workers/:id/handoff.json` and `POST /api/runs/:id/cancel`.
   - `contract/v1.json` is a machine-readable copy: route → request and response field types, in a small JSON Schema subset.
   - `GET /api/status` gains `api: 1`. It also gains `workerEgress`: `"local"` when the worker engine's endpoint (`ANTHROPIC_BASE_URL`) is a loopback address, otherwise `"remote:anthropic"`. Relay reports where its workers send the brief; Nova never guesses.
   - The "busy" answer when the single run slot is taken is documented and stable: HTTP 409 with `code: "runtime_busy"`.
3. **Contract tests.**
   - An HTTP-level test validates every v1 route's real responses against `contract/v1.json`.
   - A fake worker CLI is shipped as a fixture: `test/fixtures/fake-claude-worker.mjs`. It answers `--help` with the flags Relay detects, writes scripted files in its folder, and emits a stream-json `result`.
   - One end-to-end HTTP test goes from brief to worktree to diff, with no model.
4. **`npm run check`** covers every runtime module. Today it misses `workers.mjs`, `projects.mjs`, `profiles.mjs` and `task-plan-prompt.mjs`.
5. **Documented limits:**
   - one run slot;
   - the fixed 900 s worker timeout;
   - no cost cap;
   - worktrees are kept until the person removes them. That's the policy, written down; no new cleanup route.
6. **Browser tests:** `scripts/browser-test.sh` runs `test:browser` in the Playwright container that matches Relay's Playwright version, the way Nova's `scripts/ui-test.sh` does. It never uses sudo. The README names the prerequisite.

**Done means:**
- `npm test`, `npm run check` and the browser suite (in the container) all green, with counts in the PR;
- the PR merged to Relay's main, with tag `v0.9.0`.

## 2. Nova's adapter (M8b): `src/core/providers/relay.ts`

- **What it is.** A new built-in implementation, `relay`: class `coding-agent`, transport `http`. It is registered like the others (`IMPLEMENTATIONS`, builtins, its manifest).
- **Config.**
  - `base_url`: loopback only (`http://127.0.0.1:*` or `http://localhost:*`), because Relay binds loopback.
  - `profile`: a Relay profile name, defaulting to Relay's first worker-capable profile.
  - It has no secrets.
- **Health.** Health calls `GET /api/status`:
  - `api !== 1` → "this Relay speaks a different contract than Nova (v1)";
  - unreachable → "Relay isn't running at …";
  - no worker engine → "Relay has no worker engine".
- **Where the data goes:** whatever Relay reports in `workerEgress`. A local-only task is refused unless Relay reports `local`, checked again when the task starts. Receipts record Relay's report, for example `remote:anthropic via relay`.

**A run.** The work happens in the task's own folder (`cwd`), so Nova's verification is unchanged:
1. Copy the task's editable files into `stateDir/repo`, run `git init`, and commit a baseline. Never put a `.git` inside the task folder.
2. Connect that repo as a Relay project, create the task (goal + scope → `outcome`), and mark it ready.
3. Start the worker with `check: 'none'`, so Nova's own ask-before-running-tests step stays Nova's. The `requestId` is derived from the task's idempotency key plus the attempt number, so a retry never starts a second run.
4. Poll `GET /api/workers/:id`, and keep going while Relay's status advances.
   - **Cancel:** an aborted signal calls `POST /api/runs/:id/cancel`.
   - **Busy:** a 409 `runtime_busy` → the task waits with "Relay is busy with another run" and tries again later. That is safe, since the worker only edits a copy.
5. **On `completed`:**
   - Copy `review.files` from `worktree.directory` back into `cwd`, deletions included.
   - If Relay's file list and what was actually copied differ, fail with that reason.
   - Return `done`, with `summary = text` and usage from `usage` + `costUsd`.
   - Attach an artifact `{kind: 'relay-run', ref: runId, worktree, branch, baseCommit}`, plus Relay's diff, as provider-reported evidence.
6. **Nova's own checks still decide.** The registry's finish step computes `file_diff`, asks before running the brief's test, and runs `test_result` itself. Relay's own claim is never the verdict.
7. **On `failed`, `cancelled` or `interrupted`:** failed or cancelled, with Relay's own reason in plain words. Nothing is copied back.

**Not here:** Relay's accept/merge into a real repo. That's a later mode, where Nova would verify `git diff baseCommit` in the kept worktree. The ledger notes it.

**Stand-in: `scripts/stand-ins/fake-relay.js`.**
- It speaks contract v1 over HTTP and creates real git worktrees with scripted edits, honest or lying.
- It's validated against `tests/support/relay-contract-v1.json`, a copy of Relay's `contract/v1.json`, with the source commit noted.
- The opt-in real test checks that the copy matches the real Relay's file byte for byte, so the stand-in can't drift silently.

**PWA.** Settings › Providers shows Relay like the other providers: health, address and profile, with no special UI. The task view shows the Relay run id and branch from the artifact.

## 3. Gate (M8c)

**`tests/acceptance/m8-relay.test.ts`** (CI, stand-in): the M5 calc brief, briefed from Nova to the `relay` provider.
- Relay's worker edits it in a worktree, and Nova copies it back after its own checks.
- The task ends `done`, with `file_diff` and `test_result` verified and the `relay-run` artifact recorded.
- A lying Relay run fails with the verifier's reason, and nothing is copied back.
- A local-only task is refused while Relay reports remote egress.
- Cancel mid-run reaches Relay.
- `runtime_busy` waits and then completes.
- The egress tripwire stays empty.

**`tests/acceptance/m8-relay-real.test.ts`** (opt-in: `NOVA_RELAY_DIR=<a Relay checkout at v0.9.0>`): the same brief, against the **real Relay**.
- Relay gets a fresh data folder and an ephemeral port, with `RELAY_CLAUDE_BIN` set to Relay's fake worker fixture.
- Nova sends the brief, and a Relay worker runs in a real git worktree.
- Nova verifies the work and gets the diff evidence back.
- The test also checks the contract copy against the real Relay's file.
- With `NOVA_RELAY_MODEL=<ollama model>`, Relay runs the real `claude` CLI against the local Ollama's Anthropic-compatible API. That run is free and local, and Relay must report `workerEgress: local`.
- It writes `docs/evidence/m8-gate.md`.

**Owner checks:** a Relay run on the owner's own Claude subscription, when they choose; Relay's accept/merge into a real repo.

## Order

M8a (Relay) and M8b (Nova adapter, against the stand-in) run in parallel, both built to the interface above. M8c runs last, against the merged Relay v0.9.0.
