# M8 plan: the Relay adapter

This plan covers roadmap item M8. The packet sources are:
- ROADMAP-AND-GATES M8;
- SYSTEM-MAP: Relay is a standalone worker service, integrated by adapter, and never rebuilt into Nova;
- ADR-8: vendor agents and worker services are adapters behind Nova's own contracts;
- CONTRACTS §1 (the task envelope);
- CAPABILITY-INVENTORY (Relay integration row);
- OPERATING-RULES, including local-only never falling back to cloud, not even with a warning.

The roadmap describes M8 in three parts:
- Relay is stabilized standalone first, in its own bounded pass: interface freeze, tests green, contracts documented.
- Nova then gets an adapter to Relay over the task envelope.
- **Gate:** a coding task briefed from Nova is executed by Relay workers in worktrees, and reported back with diff evidence.

**What we start from:** a survey of `jeremyspofford/relay` at `73d801c`, v0.8.0.
- `npm test` passes 144 of 144, and `npm run check` is green.
- `test:browser` fails 7 of 7 on this machine because Chromium's system libraries are missing. That's environmental, not a code fault.
- Relay is loopback-only, with no auth. Every POST and PATCH must carry the `X-Relay-Client: relay-local` header.
- Starting a worker takes five calls: connect project, create task, mark ready, pick profile, start worker.
- There is no per-run read. A caller has to pull the whole store or follow server-sent events.
- Only one run happens at a time.
- Claude is the only worker engine. Workers run in `<data>/worktrees/<runId>` on branch `relay/<runId>`. The diff comes back on the run record as `review.diff`.

**Hard limits:**
- No accounts and no spending.
- Relay is private and Nova is public, so Nova's CI can't fetch Relay. No deploy keys or tokens get created for it, because that would be a new credential.
- Nova's CI tests the adapter against a stand-in that follows Relay's written contract. The real Relay is exercised locally, through an opt-in test.
- No new CI for Relay. Relay is private, so Actions minutes could cost money. Relay's green tests are run locally and recorded in its PR.
- Real worker runs use Relay's fake worker CLI, or the local model through Ollama's Anthropic-compatible API. Both are free. No run uses the owner's Claude subscription without a fresh OK.

## 1. Relay stabilization (M8a): in the Relay repo, PR to its main

This work runs in a fresh clone, on branch `stabilize/contract-v1`. It does no redesign. The goal is to freeze what Nova uses and write it down. The version goes to 0.9.0.

1. **A per-run read.**
   - `GET /api/workers/:id` returns one worker run record: id, taskId, projectId, status, text (the handoff summary), usage, costUsd, worktree `{directory, branch, baseCommit}`, validation, review `{files, totalFiles, diff, truncated}`, error, createdAt and finishedAt. It answers 404 for an unknown id.
   - `GET /api/workers/:id/handoff.json` serves the handoff Relay already writes.
2. **Contract v1, written down.**
   - `docs/contract-v1.md` gives request and response shapes, statuses and error codes. It covers the routes an outside client uses: `GET /api/status`, `POST /api/projects`, `POST /api/tasks`, `PATCH /api/tasks/:id`, `GET /api/state` (profiles only), `POST /api/workers`, `GET /api/workers/:id`, `GET /api/workers/:id/handoff.json` and `POST /api/runs/:id/cancel`.
   - `contract/v1.json` is a machine-readable copy: route → request and response field types, in a small JSON Schema subset.
   - `GET /api/status` gains `api: 1`. It also gains `workerEgress`: `"local"` when the worker engine's endpoint (`ANTHROPIC_BASE_URL`) is a loopback address, otherwise `"remote:anthropic"`. Relay reports where its workers send the brief; Nova never guesses.
   - The "busy" answer when the single run slot is taken is documented and stable: HTTP 409 with `code: "runtime_busy"`.
3. **Contract tests.**
   - An HTTP-level test validates every v1 route's real responses against `contract/v1.json`.
   - A fake worker CLI is shipped as a fixture: `test/fixtures/fake-claude-worker.mjs`. It answers `--help` with the flags Relay detects, writes scripted files in its folder, and emits a stream-json `result`.
   - One end-to-end HTTP test goes from brief to worktree to diff, with no model.
4. **`npm run check`** covers every runtime module. Today it misses `workers.mjs`, `projects.mjs`, `profiles.mjs` and `task-plan-prompt.mjs`.
5. **Documented limits:**
   - one run slot;
   - the fixed 900 s worker timeout;
   - no cost cap;
   - worktrees are kept until the person removes them. That's the policy, written down; no new cleanup route.
6. **Browser tests:** `scripts/browser-test.sh` runs `test:browser` in the Playwright container that matches Relay's Playwright version, the way Nova's `scripts/ui-test.sh` does. It never uses sudo. The README names the prerequisite.

**Done means:**
- `npm test`, `npm run check` and the browser suite (in the container) all green, with counts in the PR;
- the PR merged to Relay's main, with tag `v0.9.0`.

## 2. Nova's adapter (M8b): `src/core/providers/relay.ts`

- **What it is.** A new built-in implementation, `relay`: class `coding-agent`, transport `http`. It is registered like the others (`IMPLEMENTATIONS`, builtins, its manifest).
- **Config.**
  - `base_url`: loopback only (`http://127.0.0.1:*` or `http://localhost:*`), because Relay binds loopback.
  - `profile`: a Relay profile name, defaulting to Relay's first worker-capable profile.
  - It has no secrets.
- **Health.** Health calls `GET /api/status`:
  - `api !== 1` → "this Relay speaks a different contract than Nova (v1)";
  - unreachable → "Relay isn't running at …";
  - no worker engine → "Relay has no worker engine".
- **Where the data goes:** whatever Relay reports in `workerEgress`. A local-only task is refused unless Relay reports `local`, checked again when the task starts. Receipts record Relay's report, for example `remote:anthropic via relay`.

**A run.** The work happens in the task's own folder (`cwd`), so Nova's verification is unchanged:
1. Copy the task's editable files into `stateDir/repo`, run `git init`, and commit a baseline. Never put a `.git` inside the task folder.
2. Connect that repo as a Relay project, create the task (goal + scope → `outcome`), and mark it ready.
3. Start the worker with `check: 'none'`, so Nova's own ask-before-running-tests step stays Nova's. The `requestId` is derived from the task's idempotency key plus the attempt number, so a retry never starts a second run.
4. Poll `GET /api/workers/:id`, and keep going while Relay's status advances.
   - **Cancel:** an aborted signal calls `POST /api/runs/:id/cancel`.
   - **Busy:** a 409 `runtime_busy` → the task waits with "Relay is busy with another run" and tries again later. That is safe, since the worker only edits a copy.
5. **On `completed`:**
   - Copy `review.files` from `worktree.directory` back into `cwd`, deletions included.
   - If Relay's file list and what was actually copied differ, fail with that reason.
   - Return `done`, with `summary = text` and usage from `usage` + `costUsd`.
   - Attach an artifact `{kind: 'relay-run', ref: runId, worktree, branch, baseCommit}`, plus Relay's diff, as provider-reported evidence.
6. **Nova's own checks still decide.** The registry's finish step computes `file_diff`, asks before running the brief's test, and runs `test_result` itself. Relay's own claim is never the verdict.
7. **On `failed`, `cancelled` or `interrupted`:** failed or cancelled, with Relay's own reason in plain words. Nothing is copied back.

**Not here:** Relay's accept/merge into a real repo. That's a later mode, where Nova would verify `git diff baseCommit` in the kept worktree. The ledger notes it.

**Stand-in: `scripts/stand-ins/fake-relay.js`.**
- It speaks contract v1 over HTTP and creates real git worktrees with scripted edits, honest or lying.
- It's validated against `tests/support/relay-contract-v1.json`, a copy of Relay's `contract/v1.json`, with the source commit noted.
- The opt-in real test checks that the copy matches the real Relay's file byte for byte, so the stand-in can't drift silently.

**PWA.** Settings › Providers shows Relay like the other providers: health, address and profile, with no special UI. The task view shows the Relay run id and branch from the artifact.

### §2 as built (M8b, branch `m8b/relay-adapter`)

Built against Relay v0.9.0's real contract (`contract/v1.json` and `docs/contract-v1.md` at commit `4add265`), which landed while this was in progress.

**Modules.**
- `src/core/providers/relay.ts`: the `relay` implementation.
- Registered like the other built-ins:
  - `IMPLEMENTATIONS` in `types.ts`;
  - the manifest and its two settings fields in `builtins.ts` (`id: relay`, `agent-adapter`, class `coding-agent`, transport `http`);
  - the registry's implementation map.
- PWA: one line in `evidenceViewer` (`ui/js/components.js`), "Done by Relay run <id>, branch relay/<id>.", read from the report's `relay-run` artifact. Settings › Providers needed nothing new.

**Each item:**
- **Config.**
  - `base_url`: `http://127.0.0.1:<port>` or `http://localhost:<port>` with nothing after it. The default is Relay's own default, `http://127.0.0.1:8766`.
  - Relay is always called as `127.0.0.1:<port>`, so the Host it checks is that, and Node's fetch sends no Origin.
  - `profile`: a name, matched exactly, then without regard to case.
  - Hidden settings: `poll_ms` (default 1000), `busy_retry_s` (default 30) and `timeout_s`.
  - No secrets.
- **Health.** `GET /api/status`, answering in plain words:
  - "Relay isn't running at 127.0.0.1:<port> (…)";
  - "This Relay speaks a different contract than Nova (v1): it says api …";
  - "Relay has no worker engine: none of its engines can run workers right now", when no `engines[].workersAvailable` is true.
  - An implementation flag, `plainProbe`, keeps these from being prefixed "Unreachable."
- **Where the data goes.**
  - A new optional hook, `Impl.reportedWhere(c)`, comes before the address rule in `where()`. It returns what Relay last said: `workerEgress` `local` → local; `remote:anthropic` → remote, receipt `remote:anthropic`.
  - Before any check, the egress is unknown and counts as remote.
  - A check of Relay is never held back under local-only, because its address is always loopback.
  - The registry checks Relay again at the start of every run, before the privacy gate. A local-only task then waits ("Waiting on local capacity: … off your devices …") and Relay hears nothing.
- **The run.**
  1. **The repository.** Each attempt commits the task folder's files into a fresh repository at `stateDir/relay/attempt-<n>/repo`. That folder is under `workers/`, which the home's git and sync both leave out, and it skips any `.git` path. Git runs with no hooks, no signing, no system config and no `GIT_*` variables.
  2. **Relay's side.** Nova then:
     - connects that repository as the project, and refuses if Relay's `commit` isn't the commit Nova made;
     - sends `POST /api/tasks` (title: the goal's first line, at most 120 characters; outcome: the agent prompt, i.e. goal, files, scope and test line, at most 10,000), then `PATCH` it to ready;
     - picks the profile;
     - starts `POST /api/workers` with `check: 'none'`, `allowTests: false`, `context` set to the system line, and `requestId = requestId(idempotency_key, attempt)`. That is a sha256 formatted as a v5-style UUID.
  3. **Polling.** Nova reads `GET /api/workers/:id` every `poll_ms`. It tolerates 404s and failed reads for up to a minute, because Relay saves its state about every 300 ms.
  4. **Abort.** An abort (a cancel, or the ledger's timeout) sends `POST /api/runs/:id/cancel`.
  5. **An earlier attempt's run.** If it is still going, it is cancelled first (`last-run.json`).
- **Busy.**
  - `409 {code: 'runtime_busy'}` makes the task wait: "Blocked: Relay is busy with another run. Nova asks it again by itself."
  - Two new optional fields on `WorkOutcome` carry this: `retry_after_s` and `artifacts`.
  - The registry notes `retry_later` in the ledger and retries after `busy_retry_s`. The timers are re-armed by `providers.recover()` after a restart and cleared by `providers.stop()`.
- **Copy-back.** It runs only on `completed`, after these checks:
  - the worktree must exist and start from Nova's commit;
  - `review.totalFiles` must equal `review.files.length`;
  - no path is absolute, contains `..` or `.git`, or is empty;
  - Nova's own read of the worktree (`git diff --name-only <base>` plus untracked files) must equal Relay's list. Otherwise the run fails with "Relay's file list and its worktree differ: it changed X without listing it; it listed Y, which didn't change. Nothing was copied back."
  - Every path is checked with `safePath` before anything is written. Only plain files are copied. A listed path missing from the worktree is a deletion.
- **Relay's other outcomes.** `failed`, `cancelled` and `interrupted` end `failed`, with Relay's `error` in the sentence. Nothing is copied.
- **The artifact.** `{kind: 'relay-run', ref: runId, worktree, branch, baseCommit, profile, files, diff (at most 64 KB), diff_truncated, reported_by: 'relay'}`.
  - It is attached to the done report, to the partial report that asks before the test, and through the test-run approval (`TestAsk.artifacts`).
  - It is never evidence: `file_diff` and `test_result` are the registry's own, as for every coding agent.
- **The stand-in, `scripts/stand-ins/fake-relay.js`.** It serves all nine v1 routes with Relay's rules:
  - the Host and Origin checks; the header, JSON and 32 KB limit on every mutation;
  - one run slot; dedup of a project and of a `requestId`; a 202 `failed` for a stale `baseCommit`; 404 before the handoff exists; a read lag (`lagMs`);
  - real worktrees on `relay/<runId>`, with a review read by git.
  - Its modes: `honest`, `lying`, `mismatched`, `failing`, and `script`, which takes Relay's fake-worker script format `{writes, summary, delayMs, error}`.
  - Its other knobs: `busy: N`, `slowMs`, `workerEgress`, `workers: false` and `api`.
- **The contract copy.** `tests/support/relay-contract-v1.json` is Relay's file byte for byte. `tests/support/relay-contract.ts` ports Relay's `test/contract-schema.mjs`, and `tests/core/relay-stand-in.test.ts` validates every request and response against it.

**A busy answer isn't an attempt** (the M8 review asked for this; branch `m8b/relay-adapter`).
- **The ledger.** It gained `notStarted(id, why)`, which a running worker calls when the service it hands work to turned the work away before anything existed.
  - Only a `blocked` report takes the claim. The ledger then gives the dispatch back (`attempts - 1`) and records `attempt_returned` with "Relay was busy; this didn't count as an attempt." The task waits with the worker's reason as before.
  - A `done` or `failed` report is counted whatever was claimed, and so is a blocked report without the claim.
  - After a restart, an active task whose last dispatch claimed not-started is given back before it is requeued.
- **Providers.** A provider returns `not_started` on its blocked outcome. Relay does so only for `runtime_busy`; any run that existed, even one cancelled at once, is an attempt.
- **The `requestId` after a give-back.** The next real attempt reuses the same attempt number, so the same `requestId`.
  - This can't collide with a run Relay started. In Relay's `runtime/workers.mjs`, the lookup by `requestId` (lines 77–81) comes before the busy check (line 84), and a run is recorded only after both (line 100). A busy answer leaves no record, so the later start under that id is a fresh run.
  - `tests/core/relay.test.ts` checks this: 4 busy answers, a run that fails verification, then an honest run ends done, with 2 Relay runs and the busy asks sharing the first real run's `requestId`.
  - The task's count is 4: each real run is followed by the dispatch that runs the test once the person OKs it, as with no busy answers.
- **Tests.** `tests/core/ledger-not-started.test.ts` covers the ledger rules.

**Deviations, with reasons.**
- **Receipts record Relay's report as the egress.** For example `remote:anthropic` or `local`, with provider `relay` and model `Relay worker (<profile>)`. They don't say "remote:anthropic via relay": the receipt format allows only `local` or `remote:<name>`, and the provider field already names Relay.
- **A local-only task that Relay's fresh report rules out at start waits instead of failing.** It waits with the usual "Waiting on local capacity" reason, as every other provider does. At creation it is refused (400).
- **The provider's own summary is replaced after the person OKs the test run.** That is existing registry behaviour for every provider. Relay's text is in the partial report and the artifact.
- **The default profile is the first one whose engine has `workersAvailable`.** That is what Relay's contract says, rather than a field on the profile.

**Known gaps.**
- **Worktrees and repositories are kept.** Relay keeps every worktree, and each attempt's repository under `stateDir` stays too. There is no cleanup, by Relay's policy.
- **Accept/merge into a real repository is a later mode**, as the plan says.

## 3. Gate (M8c)

**`tests/acceptance/m8-relay.test.ts`** (CI, stand-in): the M5 calc brief, briefed from Nova to the `relay` provider.
- Relay's worker edits it in a worktree, and Nova copies it back after its own checks.
- The task ends `done`, with `file_diff` and `test_result` verified and the `relay-run` artifact recorded.
- A lying Relay run fails with the verifier's reason, and nothing is copied back.
- A local-only task is refused while Relay reports remote egress.
- Cancel mid-run reaches Relay.
- `runtime_busy` waits and then completes.
- The egress tripwire stays empty.

**`tests/acceptance/m8-relay-real.test.ts`** (opt-in: `NOVA_RELAY_DIR=<a Relay checkout at v0.9.0>`): the same brief, against the **real Relay**.
- Relay gets a fresh data folder and an ephemeral port, with `RELAY_CLAUDE_BIN` set to Relay's fake worker fixture.
- Nova sends the brief, and a Relay worker runs in a real git worktree.
- Nova verifies the work and gets the diff evidence back.
- The test also checks the contract copy against the real Relay's file.
- With `NOVA_RELAY_MODEL=<ollama model>`, Relay runs the real `claude` CLI against the local Ollama's Anthropic-compatible API. That run is free and local, and Relay must report `workerEgress: local`.
- It writes `docs/evidence/m8-gate.md`.

**Owner checks:** a Relay run on the owner's own Claude subscription, when they choose; Relay's accept/merge into a real repo.

### §3 as built (M8c, branch `m8b/relay-adapter`)

- **The CI half: `tests/acceptance/m8-relay.test.ts`, against the stand-in.** It covers every CI bullet above in one real server process, with the egress tripwire on.
- **The real-Relay half: `tests/acceptance/m8-relay-real.test.ts`.** It is opt-in, run with `NOVA_RELAY_DIR=<Relay checkout>`.
  - Relay runs as its own process: `node --import <Nova's egress tripwire> server.mjs`, run from the checkout, which is only read.
  - Its port is ephemeral. `RELAY_DATA_DIR` is a fresh temporary folder and `HOME` is a fresh empty one.
  - The process is stopped by its own pid in `finally`.
- **Three tests:**
  - The contract copy is compared byte for byte with `contract/v1.json`.
  - **The fake worker run:** Relay's own `test/fixtures/fake-claude-worker.mjs` is `RELAY_CLAUDE_BIN`, and Relay runs it directly (it has a shebang). `ANTHROPIC_BASE_URL=http://127.0.0.1:9`, so Relay reports local.
  - **The model run**, with `NOVA_RELAY_MODEL`: the real `claude` CLI against the local Ollama, with `ANTHROPIC_BASE_URL=http://127.0.0.1:11434`, `ANTHROPIC_AUTH_TOKEN=ollama`, `ANTHROPIC_API_KEY` empty, `ANTHROPIC_MODEL`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` and the fresh `HOME`.
- **Both runs send the calc/ brief local-only.** They write their part of `docs/evidence/m8-gate.md`.
- **Results, 2026-10-30, Relay 0.9.0 at `4add265`:**
  - Fake worker: done and verified in about 1 s.
  - `qwen3-coder:30b` through Claude Code 2.1.259 and Ollama 0.40.0: done and verified. It took 102 s on the first run, while the model loaded, and 4 s on the run recorded in the evidence.
  - In both, the worktree is real and on `relay/<runId>`, and Relay's diff shows the fix.
  - The receipts say `local`. The tripwire found nothing leaving the machine, from Nova or from Relay's own process.
- **Not covered by the tripwire:** the claude CLI is a native binary that Nova's Node tripwire can't wrap. For it, the evidence is its settings and Relay's report of `workerEgress: local`.

## Order

M8a (Relay) and M8b (Nova adapter, against the stand-in) run in parallel, both built to the interface above. M8c runs last, against the merged Relay v0.9.0.
