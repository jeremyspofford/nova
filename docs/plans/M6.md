Roadmap M6. The packet sources are:
- CONTEXT-AND-CAPTURE;
- LOCAL-MODELS;
- LOCAL-FIRST-AND-DEVICE-MESH §1–§2;
- ADR-2, ADR-7 and ADR-10;
- CONTRACTS §1–§2 and §7;
- NOVA-SPEC §5–§7;
- OPERATING-RULES, including the owner's standing orders: local-only never falls back to cloud, not even with a warning, and forgetting holds everywhere.

The inventory rows are 34 and the capture/model rows.

**Gate:** a full day-in-the-life run in local-only mode on hub-class hardware.

**This machine** (the hub for the gate): 20 threads, 31 GB RAM, RTX 3090 with 24 GB, and Ollama with 16 models installed. Screenpipe and a transcription runtime are not installed.

**Hard limits:**
- No accounts and no spending.
- Tests and CI use stand-ins: an Ollama-compatible server, a Screenpipe-compatible server, and a Wake-on-LAN listener.
- The real day-in-the-life runs locally against the real Ollama, using models that are already installed.
- No multi-GB model download happens without the owner asking for it. The download path is tested against the stand-in, plus at most one small real pull.

**Rules as before:**
- no runtime dependencies;
- erasable TypeScript in `src/core`, vanilla JS in `ui/`;
- neutral placeholders;
- tests for everything;
- code outside `src/core` imports only `src/core/index.ts`.

## 1. Capture (M6a) — `src/core/capture/*`

**Capture API.**
- **Call shape:** `capture.stream(device, kind)` produces normalized events. `kind` is `screen`, `audio`, `meeting`, `browser`, `app-activity` or `sensor`.
- **Each event carries:** timestamps, device, source, consent state, a space-attribution hook and provenance.
- **Consumers** never know which source produced an event.

**Consent.**
- Capture is off by default, and is enabled per source and per device.
- While any source is active, a visible indicator shows in the PWA: on the orb or top bar, on every page.
- Every source can be paused, and has exclusions per app, per site, per space and per time window.
- Private and incognito contexts are never captured: sources mark them and the API drops them.

**Storage.**
- Captured data is stored on the hub first (`node:sqlite`, migration `0009`), classified by space, with provenance.
- Retention is a profile policy, enforced by a sweep.
- Deletion is real deletion: it holds in backups and on the standby, following memory's forget path and M4's sync.

**Capture is evidence, not memory.** Promotion to memory is deliberate and auditable: the person does it, or a triage decision with an escape proposes it. It follows CONTRACTS §7, with provenance pointing back to the capture events.

**Classification.** Spaces are attributed by signals the person configures: active app, calendar, device, or an explicit switch. Ambiguous activity stays unclassified and is never guessed. Folder paths are never used.

**Screenpipe-compatible ingest** is the first adapter. It pulls a local Screenpipe's REST API (OCR text, audio transcripts, app and window), so existing Screenpipe pipelines flow in unchanged. It is tested against a stand-in Screenpipe server.

**Device sources.** A paired computer's runtime agent can send capture events through M4's inbox (`capture_event`, exactly once). Desktop app-activity is the native source to start with, where it can be read without new OS permissions; otherwise it is documented as a later native component (ADR-2).

**Platform posture.** Setup and Settings › Capture say plainly what each platform can capture:
- desktop: deep, under OS permissions;
- Android: accessibility and notification permissions;
- iOS: no passive capture of other apps. Only what the platform offers.

**PWA: Settings › Capture.** Sources per device, consent, pause, exclusions, retention, the indicator, and a Capture view: recent events, unclassified items to resolve, and promote-to-memory. The view follows the perception principles: real state only, and recommend rather than list.

## 2. Local models (M6b) — `src/core/models/*`

**Hardware detection** per device:
- what it reads: CPU, RAM, GPU/VRAM and disk;
- how: `nvidia-smi`, `rocm-smi`, `system_profiler` and `/proc`, as available, plus the platform's own tools;
- across the mesh: devices report it in their M4 heartbeat capabilities, which builds the mesh-wide capability map.

**Recommendation.** Roles are `triage-text`, `reasoner`, `embedder` and `transcriber`.
- **What Nova recommends:** a small set that fits each device's VRAM/RAM, with plain-language trade-offs (speed, depth, size).
- **It recommends models already installed when they fit.**
- **It is honest when a role has no runtime here.** Transcription with no whisper runtime says so, and the role stays unassigned.

**Download and lifecycle** go through the runtime adapter:
- Ollama `/api/pull` streaming, with progress in the PWA;
- an integrity check by digest, versions recorded;
- a disk budget in the profile, refused when it would be exceeded;
- removal through `/api/delete`.

A download is a tier-2 ledger task with evidence: the digest, verified by Nova reading `/api/show` or `/api/tags` itself.

**Serving.**
- **Runtimes are adapters.** Ollama comes first, with OpenAI-compatible endpoints as M5's adapter.
- **One internal inference API.** Callers name a role, never a model or binary: `models.infer({role, messages | input, privacy_mode})`.
- **Routing:** roles are assigned to device and model in the profile. M5's `openai-compatible` provider and the chat runner use this API when the chat choice is "local".

**GPU spoke, wake and serve.** A paired computer with a GPU can serve roles.
- The hub sends a Wake-on-LAN magic packet (UDP broadcast to the device's MAC, which comes from its heartbeat).
- It waits up to that device's measured wake latency, serves, and lets the device sleep after idle (the device agent's policy).
- Scheduling is honest about wake latency: small jobs stay on the hub.

**Fallback chains** (LOCAL-MODELS worked examples, evaluated inside the task's privacy mode):
- local reasoner down, task local-preferred: the cloud serves, the receipt says so, and a problem is opened for the local fault;
- cloud unreachable, task cloud-allowed: the local reasoner serves, and the report says when depth may be lower;
- local-only task, local reasoner down: the task waits with "waiting on local capacity", the person is told per proactivity, and it is **never** served by cloud. When capacity returns, it runs.

**Local Decision Model Provider (ADR-7).** It implements the M2 `DecisionProvider` interface on the `triage-text` role: Choice, Score and Noul as typed JSON, schema-checked, and anything out of schema escalates. In local-only mode only local providers run, and receipts name the provider.

**Budgets.** Cloud spend has per-task and per-period budgets in the profile. Usage from every report is tracked in the ledger. Over budget: the task waits with the reason, and local stays the default answer.

**PWA: Settings › Models.** The device map, what's recommended and why, assigned roles, downloads with progress and digest, the disk budget, and the cloud budget.

## 3. Gate (M6c) — `tests/acceptance/m6-day.test.ts` (stand-ins, CI) + `tests/acceptance/m6-day-real.test.ts` (opt-in, the real Ollama)

A **day in the life, local-only from setup to night**, on a test clock that moves a day forward in minutes:
1. **Fresh profile, set up as local-only.** The model manager detects the hardware, recommends and assigns roles from installed models, and says plainly that transcription has no runtime.
2. **Morning.** Capture is enabled for a Screenpipe-compatible source; the indicator is visible. Events flow in through the day (apps, OCR text) and are classified by the person's signals; ambiguous ones stay unclassified. A private window is never stored.
3. **Triage.** Event and heartbeat triggers through the **local** Decision provider, with Noul and Choice. Receipts name the local provider.
4. **Chat** through the local reasoner, with a receipt per call, egress `local`.
5. **Delegated work.** The M5 calc brief through the local model, with Nova's own test run approved and verified.
6. **Memory.** The person promotes one captured fact to memory, with provenance back to the capture. Later they forget it: it's gone from memory, capture, backups and the standby (if one is paired in the CI variant).
7. **Midday outage.** The local reasoner goes down: the stand-in is stopped, or in the real run the role is pointed at a dead port, which is said plainly. A local-only task waits with "waiting on local capacity", the person is told, and nothing goes to the cloud. Capacity comes back and the task runs.
8. **Evening.** Retention sweeps old capture. A cloud budget is set but never used.
9. **All day:** the egress tripwire log stays empty, and every receipt is local.

**Evidence:** `docs/evidence/m6-day.md` with timings, models used, receipts, and the outage handling.

**Owner checks:**
- real Screenpipe;
- a real GPU spoke woken over the LAN;
- real model downloads they choose.

## Order

M6a and M6b run in parallel. Each keeps its edits to shared files small and additive, and each numbers a migration `0009` (the integrator renumbers). The gate (M6c) comes last.
