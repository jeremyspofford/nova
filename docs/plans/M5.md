# M5 plan — agents and integrations

Roadmap M5. The packet sources are:
- CONTRACTS §1 (envelope), §2 (receipts), §4 (manifest);
- EXTENSION-MODEL (kinds: agent adapter, automation adapter, connector);
- NOVA-SPEC §6 (tiers);
- LOCAL-FIRST §2 (privacy modes);
- ADR-6 and ADR-8 (vendor SDKs are adapters behind Nova's contracts);
- WORK-LEDGER-AND-VERIFICATION;
- DESIGN-SYSTEM, including the perception principles.

The capability inventory rows are 12, 40, 42–46 and 58.

**Gate:**
- the same brief is executed by two different providers through the envelope;
- the evidence is verified for both;
- a task is taken over and handed back mid-task.

**Hard limits for this milestone (OPERATING-RULES):**
- No external accounts are created and no money is spent. Tests and CI use stand-ins that speak each provider's real protocol (the CLIs' JSON event streams, the OpenAI-compatible HTTP API, n8n's webhooks, Home Assistant's REST and WebSocket APIs).
- One real provider runs locally for evidence: **Ollama**, which is free and already serves a model on this machine.
- A real **Claude Code** evidence run needs the owner's OK first, because it uses their subscription.
- Codex, n8n and Home Assistant aren't installed here. Their adapters are built and tested against stand-ins, and checking them for real is listed for the owner.

**Rules as before:**
- no runtime dependencies;
- erasable TypeScript in `src/core`, vanilla JS in `ui/`;
- neutral placeholders;
- tests for everything;
- code outside `src/core` imports only `src/core/index.ts`.

Era 1 is the reference for:
- the provider contract and its adapters: `packages/providers/src/{types,wire,sse,collect,openai-compatible,mock}.ts` at `6e2cf142`, plain `fetch` + SSE;
- the ACP host: `packages/core/src/acp/*`;
- the vault: `packages/secrets/src/{vault,keychain,select}.ts`;
- browser takeover: `packages/core/src/browser/session.ts`. Era 1 used Playwright at runtime; we drive Chromium over CDP ourselves.

## 1. Providers (M5a) — `src/core/providers/*`, migration as needed

**The registry generalizes `agent_cmd`.**
- **What a provider is:** an extension of kind `agent-adapter` or `automation-adapter` (EXTENSION-MODEL), with the CONTRACTS §4 manifest plus `adapter`:
  - `class`: `coding-agent` | `chat` | `automation`;
  - `transport`: `cli` | `http`;
  - `egress`: `none` | `local` | `remote:<host>`;
  - `capabilities[]`, `config` (command or base URL, model) and `secrets[]` (names only).
- **Each enabled provider is a ledger Worker.**
  - It runs a Brief and returns a Report through the envelope (CONTRACTS §1).
  - It is gated by `permits(privacy_mode, egress)`.
  - Every model or agent call records a context receipt (CONTRACTS §2).
- **Health.** "Installed / not installed / not configured / unreachable", in plain words.

**Built-in adapters (installed, enabled only when configured):**
- **`claude-code`** (coding agent, CLI). `claude -p --output-format stream-json` in the task's workspace. Egress `remote:anthropic`.
- **`codex`** (coding agent, CLI). `codex exec --json` in the task's workspace. Egress `remote:openai`.
- **`openai-compatible`** (chat, HTTP). This is Era 1's adapter, ported: `fetch` + SSE, base URL and model, and a key from the vault when one is needed.
  - **The Ollama profile** defaults to `http://127.0.0.1:11434/v1`. Its egress is `local` when the base URL is loopback or a mesh address, and `remote:<host>` otherwise.
  - **To act on files,** a chat provider gets the brief with a strict JSON reply contract (`{files:[{path, content}], notes}`). Nova applies that reply inside the task's workspace and nowhere else, and checks every path.
- **`custom-cli`.** Era 2's `NOVA_AGENT_CMD` becomes a provider entry, so the existing chat runner keeps working unchanged. Era 2's chat goes through the registry, using the provider the profile names for chat, which defaults to what `agent_cmd` names today.
- **`n8n`** (automation, HTTP). It covers both directions:
  - **Outbound:** POST to a workflow's webhook URL with an HMAC-SHA256 signature and the brief.
  - **The report:** comes back through Nova's existing token webhook (M2) as a callback that carries `task_id`, the result and `confirmation` evidence. Nova checks it.
  - **Inbound triggering** stays M2's webhooks.

**Per-task workspace.** A coding or chat provider works in `workspace/tasks/<task-id>/`, never anywhere else. A brief can name existing workspace files, which are copied in; the results are copied back only after verification passes.

**Verification (Nova checks it itself).**
- `file_diff` is checked against the task workspace.
- `test_result` means Nova runs the brief's declared test command itself in the task workspace, never trusting the provider's claim. It is tier 2: running a command asks first, unless policy allows it.
- `read_back` is checked as now.
- A provider that reports success with evidence that doesn't hold ends `failed`, with the verifier's reason.

**PWA:** Settings › Providers.
- Each provider shows its class, egress, health and configuration. Enable is tier 2.
- Choose the provider for chat, and the default per class. The app recommends one rather than listing options (perception principles).

## 2. Connectors and the vault (M5b) — `src/core/{vault,connectors/*}.ts`

**The vault** (inventory row 58; Era 1 port).
- **Storage:** secrets are encrypted at rest (AES-256-GCM) in `home/vault/`, mode 0600.
- **The key:** held by the OS keychain when one is available (`secret-tool` / Keychain / Credential Manager). Otherwise in `home/vault/key` (0600), and the person is told plainly that the key sits next to the vault on disk.
- **References:** `secret://<name>`.
- **Out of history:** the vault is untracked in the home's git, a test proves it, and it is redacted from logs, receipts and sync.
  - On a standby it replicates, sealed. Connectors that need it work again after a failover, which closes M4's note about `connectors/`.
- **Migration:** Era 2's plaintext connector secrets move into the vault and are deleted.

**The connector kind.** It has a manifest and owns its auth through the vault, its sync, and its events, which become M2 event triggers. Removing a connector revokes its secrets and subscriptions (EXTENSION-MODEL).

**Gmail.** Era 2's Gmail (OAuth PKCE and IMAP app password) is repackaged as a connector extension, with the same behaviour: it reads, drafts and organizes, and never sends or deletes. Its secrets move into the vault, and mail events become triggers.

**Home Assistant connector.**
- **Setup:** a base URL plus a long-lived token, kept in the vault.
- **Reads entity states** (tier 0).
- **Calling a service is tier 2,** because "changing devices/home state" asks first (NOVA-SPEC §6). Domains the person marks are tier 3.
- **State changes** arrive over HA's WebSocket API as `event` trigger records.
- **Egress** is `local` for a LAN or mesh address.
- **Testing** uses a stand-in HA server (REST + WebSocket) in the test support.

**PWA:** Settings › Connections. Connect, status, what it can do in plain words, disconnect.

## 3. Browser work with human takeover (M5c) — `src/core/browser/*`

- **A browser worker** drives Chromium over CDP: `--remote-debugging-pipe` or a port bound to loopback, using Node's built-in WebSocket client and no Playwright at runtime.
  - **Where Chromium comes from:** `NOVA_CHROMIUM` or a known install path. Health says plainly when there isn't one. The dev host here can't start Chromium; it runs in the Playwright container and in CI.
  - **What a browser task is:** steps a provider or a scripted plan chooses (navigate, fill, click, read).
  - **Egress** is declared per task as allowed hosts, and enforced by intercepting requests with CDP `Fetch`. Anything else is blocked and recorded.
  - **Page content is data, never instructions:** nothing from a page changes the task's brief or permissions.
- **Takeover (Era 1 parity: pause, resume, frame stream).**
  - **Who can take over:** the person can, at any time. The worker also requests it when a step needs a human (a login, a challenge); the task goes to `waiting` / Needs you.
  - **Live view:** the PWA shows CDP screencast frames over the core event stream, or a dedicated SSE stream.
  - **Input:** the person's pointer and keys go through `Input.dispatch*`.
  - **While taken over,** the worker does nothing.
  - **Hand-back** resumes the plan from the page's current state.
  - **The ledger** records `takeover_started` and `takeover_ended`, with who did it and for how long.
  - **Access:** only the console and `can_approve` clients can take over. A screenshot or frame is never cached by the service worker.
- **Evidence:**
  - `screenshot`, stored in the task's folder;
  - `url` with an expected-content check, where Nova re-fetches the page itself (inside the declared hosts) or reads the final DOM through a fresh CDP read;
  - a `confirmation` from the system the page talks to, when there is one.

## 4. Gate (M5d) — `tests/ui/m5-*.test.ts` plus integration tests

1. **One brief, two providers.** The brief is "make the failing test in `calc/` pass". It goes through the envelope to:
   - (a) `claude-code`, a stand-in CLI that speaks its stream-json and edits files;
   - (b) `openai-compatible`, a stand-in OpenAI-compatible server that returns the JSON files contract.

   For each, Nova runs the declared test itself, checks the diff, and the task ends Verified with evidence. Receipts show each provider's egress, and a local-only task refuses the remote provider and says why.
2. **The same, for real, locally (evidence, not CI).** `openai-compatible` against the Ollama on this machine.
   - Claude Code for real only with the owner's OK.
   - If the local model can't solve the brief, the gate records that honestly, as a failed task with the verifier's reason, and then uses a simpler brief. It never fakes a pass.
3. **Takeover and hand-back mid-task.** A browser task fills a multi-step form on a local test site, in Chromium in the container.
   - At the step marked "a person must do this", the worker requests takeover and the task shows Needs you.
   - The person, in the PWA, takes over: they see the live frame and click or type through the step, then hand back.
   - The worker finishes. Nova verifies the site's final state itself.
   - Both takeover events are in the ledger.
   - Also tested: a voluntary takeover in the middle of an agent step.
4. **n8n** round trip against a stand-in: a signed outbound call, then a callback that carries evidence.
5. **Home Assistant** against a stand-in: a state read, a tier-2 service call with confirm, and an event becoming a trigger record.
6. **Fresh-user test still passes.**

**Evidence:** screenshots in `docs/screenshots/m5/`, and a transcript in `docs/evidence/m5-gate.md`.

**Manual checks for the owner:**
- real Claude Code (with OK);
- Codex if installed;
- a real n8n workflow;
- a real Home Assistant.

## Order

M5a, M5b and M5c run in parallel. Each keeps its edits to shared files (`src/core/index.ts`, `src/server.js`, `src/core/extensions.ts`, `docs/LEDGER.md`) small and additive. The gate (M5d) comes last. Migrations: each piece that needs one numbers it `0009` on its own branch (migrations must be gapless, so a piece can't test with a later number), and the integrator renumbers them at merge.
