**2026-11-12 · Model seats · Nova keeps its own Claude sign-in, checks it every 6 hours, and asks you to sign in again from Health when it lapses (seat self-authentication, owner-approved 2026-11-12)**
- What changed: Nova's Claude CLI seat now lives in its own folder, `<Nova home>/seats/claude-cli`, and every Claude call Nova makes (the model command, Claude Code providers, the keepalive) runs with `CLAUDE_CONFIG_DIR` set to it, never against your own `~/.claude`; a call with no seat gets a signed-out folder of its own. Nothing is copied into it from anywhere, so the seat starts signed out: it is the last sign-in in the wrong place. A keepalive (src/core/claude-seat.ts) runs from the hub's heartbeat every 6 hours (`seat_probe_hours` in nova.config.json, `NOVA_SEAT_PROBE_HOURS` over it; 15 minutes while it isn't ok), and each check is kept as ok, needs-sign-in or unreachable and shown in Health as "Claude sign-in". The probe is one `claude -p` call on Haiku, one turn, with no tools, MCP servers, settings or saved session, the cheapest call that makes the CLI use and, if needed, refresh its token; `claude auth status` doesn't qualify, since it only reads the token file and never refreshes. An authentication failure in any call, or a failing probe, opens one problem, "My Claude sign-in expired" (deduplicated), red when nothing else can answer and amber while another model can. Chat and scheduled runs name the cause. The problem's one action, Sign in again, is for the console or a device allowed to approve; it starts `claude auth login` against the seat's folder, shows Claude's sign-in page as a link to open on any device, phone included, and takes the code back. The code and the address are never logged or written to Nova's home. Only Nova's own check call, made after the sign-in, closes the problem (not the login's word), and the closing is a ledger task, "Claude sign-in works again". Supporting changes: a seat that needs a sign-in no longer counts against a release in the supervisor's canary, since going back to older code can't sign Nova in; the seats folder is left out of git, backups, checkpoints and restore; and tests check the seat with a stand-in CLI, never the real one.
- What you can now do: see in Health whether Nova's Claude sign-in works and when it was last checked; sign Nova in again from the Health problem on your phone or the hub, without a terminal; rely on signing in to Claude Code in a terminal never changing what Nova uses.
