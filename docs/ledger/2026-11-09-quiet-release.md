**2026-11-09 · Inbox · Quiet hours hold messages from Nova's own parts instead of dropping them**
- What changed: when quiet hours end, the heartbeat released a held message only if its automation still existed, was on and wasn't turned off; anything else was withdrawn. Messages from Nova's own parts (Coding, Infrastructure, Network, Local models) have no automation, so every one held during quiet hours was withdrawn and listed nowhere.
  - `src/core/triggers.ts`: the release check is now `#stillStands()`. A message from an automation keeps today's rule: withdrawn if the automation was deleted, paused, or its class or name is in `proactive_off`. A message without an automation is delivered unless its class (`proactive`) or the part's name is in `proactive_off`, the same check `fire()` made when it came in.
  - The trigger record keeps the part's source (`coding`, `infra`, `network`, `models`) but not its name, so the source-to-name map is now `PARTS` in `triggers.ts`, and `src/core/index.ts` uses it for the four parts' names so the two can't drift.
  - Quiet-hours window, oldest-first release order and the waiting-for-your-OK hold are unchanged. No migration.
- What you can now do: a coding run, infrastructure run, network change or local-model notice that lands during quiet hours reaches you once they end. Turning that part (or proactive messages) off before then still withdraws it.
