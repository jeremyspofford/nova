**2026-11-06 · Models screen · A Mac's budget is its real GPU memory limit when one is set**
- What changed: on a Mac, the GPU shares the computer's memory, and macOS decides how much of it the GPU may use. Nova used to guess: 2/3 of the memory below 36 GB, 3/4 from 36 GB. Now a paired Mac (and a hub that is a Mac) reads the limit macOS actually has, with `sysctl -n iogpu.wired_limit_mb`, and sends it with its hardware. When someone has raised that limit, it is the budget every verdict on the Models screen is worked out against, and the budget line says "GPU memory limit set on this Mac: 56.0 GB", say. When it hasn't been raised (macOS reports 0, its default), can't be read, or an older Nova on the Mac doesn't send it, the old fractions are used, and the line says so: "Estimated GPU share of 16.0 GB unified memory: 10.7 GB (macOS default)". The hub only believes a reported limit that is a whole number of bytes, above 0 and no more than the Mac's memory; anything else is treated as not known. A Mac's hardware line in the Models settings ("Apple M2 (10.7 GB shared)") now shows the same budget the verdicts use, not 3/4 of the memory. The Mac itself still reports 3/4 as its GPU's figure, because the device agent can't load the fit engine; the hub replaces it when it writes the line.
- What you can now do: if you have raised the GPU limit on a Mac, Nova plans models against your limit instead of its guess. You can see which one it used on the Models screen.
- Still unfinished: the fractions Nova uses when no limit is set are still Nova's estimate of Apple's default. They haven't been checked on a real Mac. To check one, run `sysctl iogpu.wired_limit_mb` on it (0 means the default is in use), and compare the GPU memory Ollama reports for a loaded model. The sizing for the Decision Service's sorting model (Tev1) and service placement still use their own 3/4 rule.
- Checked: new tests read the limit with a stand-in for sysctl (a raised limit, 0, garbage, an error, a timeout, and other systems, where nothing runs), check what the hub refuses (negative, not whole, more than the memory, text, missing), and check that a measured 180 GB limit on a 192 GB Mac is the budget while the fallback stays at 10.7 / 27 / 48 / 144 GB for 16 / 36 / 64 / 192 GB. The styleguide has a new state for a Mac with its limit set, checked across the whole responsive matrix in both browsers, and a UI test checks both budget lines in the app. See the PR's gate table.
