**2026-11-10 · Memory · A forgotten day note is forgotten in every backup, and restores and the drill know it**
- What changed: forgetting a day note (F-009, A-020) only rewrote the live day file. No backup, encrypted copy, owed forget, checkpoint or upgrade backup was cleaned, and a restore could bring the note back. src/memory.js now hands every forgotten day note to the core, including a forgotten memory's reworded twins. The hand-off is onNoteForget, wired in server.js through the runner to core.memory.forgetNotes. The core records a content-free memory_event of kind note-forgotten, with memory_id note:<id>:<mac>, and sends the words through the same Backups.forget as a record forget. The mac is HMAC-SHA256 of the note's words under the hub's note key. That key is nova/note-forget-key in the vault, one of Nova's own keys, made on the first note forget and carried over by a restore like the others. The id is "-" for a note written by hand, because its id is made from its words. The words themselves, and any unkeyed hash of them, are never stored. The three early returns that dropped a forget with words and no ids (backups.ts, the nightly backups, checkpoints) now let it through. File cleaning (src/core/forgotten-notes.ts, scrubWords) also matches the words with whitespace collapsed, and drops a wrapped list entry whole. A restore (restore.ts) carries the note events across. It drops forgotten notes from the staged MEMORY.md and day notes by id, or by mac under the live hub's key, and drops the staged sync log's copies of those files. An undo writes note-restored, so a note put back stays. The drill and the forgotten-everywhere check (F-010) now scan each backup's manifest files for forgotten notes and memories, ignoring a note the live home shows again. Capture's "Deleted everywhere" (A-021) now also asks the nightly backups whether any folder still owes the forget (owedForgets, wired in index.ts), and names the folder when one does.
- Without the key: when the vault can't give the note key, nothing is skipped quietly. A forget still cleans every backup, keeps a Nova-written note's id, and raises a problem saying an older backup or checkpoint could bring the note back. A restore that has to find a note by its mac is refused, in words. The drill and the forgotten-everywhere check fail, and say why.
- Where the key can be read from: nightly backups and their encrypted copies hold the vault's file but never its key (backup.ts, SKIP_FILE: vault/key), so a backup alone can't open the note key or test a guessed note against a tombstone. A test checks this.
- What you can now do: forget a day note and trust that no backup, copy, checkpoint or restore keeps it; believe "Deleted everywhere" when capture says it.
- Still unfinished: checkpoints on main still copy the vault together with its key file, because #456 hasn't merged. Until it does, a checkpoint, which stays on this machine, could open the note key. A standby gets the note-forgotten event by sync but doesn't clean its own backups of a note forget. An emergency promotion on a node whose vault lacks the note key refuses to restore notes it can't find. A day note deleted by hand in the file, not through Nova, isn't recorded. Matching is case-sensitive, as before.
