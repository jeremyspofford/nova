**2026-11-09 · Tests · Two process checks no longer trip over a process exiting mid-read**
- What changed: the B3 launch test's running() helper read /proc/<pid>/stat and treated only ENOENT as "gone"; a process that exits while its stat is being read gives ESRCH instead, so the check threw at exactly the moment it should have said "not running" (seen once in CI on #430). broker-lifecycle had the same race as a check-then-read. Both now treat ENOENT and ESRCH as gone and read once. Nova's own /proc readers (supervisor procs.ts, coding preview.ts) already treat any read failure as gone.
- What you can now do: trust a B3 or broker-lifecycle failure in CI.
