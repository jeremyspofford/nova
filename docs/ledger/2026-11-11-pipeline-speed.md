**2026-11-11 · Pipeline · The UI gate runs in eight shards, blocks only UI pull requests, and a red main pauses merges**
- What changed: on the owner's pipeline ruling of 2026-11-11, the UI gate runs in eight shards instead of four, balanced by per-file times re-measured from the last ten main runs (`scripts/ui-timings.json`), each projected at about 523 s of tests. A pull request now runs the UI gate and shots only when it touches a UI surface (`ui/**`, the design systems and the code that builds served CSS and HTML, the UI test tooling, the Playwright pin, `.github/**`, and any unknown file; the exact list is in `scripts/ci-changes.sh` and `docs/PIPELINE.md`). Every merge to main still runs the UI gate and shots, whatever it touched. The gate's decision moved into `scripts/ci-gate.sh` with every combination tested. A red main gate opens a `main-red` issue, and `scripts/merge-on-green.sh`, now in the repo, merges nothing more until a pull request that says "Fixes #N" for it lands. A new push to a pull request cancels its previous run; main's runs each have their own group and are never cancelled (56 queued main runs had been cancelled under the old shared group). The preview's deploy watcher (`scripts/deploy-watch.sh`, canonical copy) deploys only main commits whose gate passed. No test was deleted, skipped or loosened.

A non-UI pull request is mergeable after its checks (about 13 minutes); its UI evidence comes from main's run, printed by the merge script as `MAIN-UI pass|fail <run url>`.
