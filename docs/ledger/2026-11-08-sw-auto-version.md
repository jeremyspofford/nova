**2026-11-08 · Pipeline · The service worker's cache name is worked out, not bumped**
- What changed: `ui/sw.js` no longer carries a hand-numbered `nova-shell-vNN`. It says `nova-shell-__SHELL_HASH__`, and the server fills in 12 hex characters of a SHA-256 over the worker itself and every file in its SHELL list (`src/sw-version.js`), worked out once at start (on every request under `npm run dev`). `/sw.js` is still `no-cache`, `text/javascript`. The activate step's cleanup now matches both `nova-shell-<12 hex>` and the old `nova-shell-v<n>` names, never another cache. Every pull request that touched the shell used to bump the same line, so any two open ones conflicted on it and each conflict cost a full CI rerun. The hash changes when the shell does, a dirty local checkout included (the build commit would not), and stays the same across restarts of one build. The worker's own text is in the hash, so a change to what it never caches still retires the old cache, as a bump did. A browser on `nova-shell-v70` sees a different worker, installs it, and deletes `nova-shell-v70` and any older numbered cache.
- What you can now do: change anything in the shell without touching `ui/sw.js`. Never edit the cache name by hand.
