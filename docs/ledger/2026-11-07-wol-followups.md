**2026-11-07 · Wake-on-LAN · Services respect computers that sleep, and Windows reports when a card can't wake**
- What changed: two follow-ups from the Wake-on-LAN feature (#360). (1) Service placement now knows each computer's sleep choices (Settings › Models › Sleep and wake). A computer that sleeps when idle is never picked as a new home for a preferred or floating service; one already running there stays while it answers (Nova holds it awake for it, as before), and pinning a service there is how to keep it awake. When the only computers that may run a service sleep by design, placement says so instead of "down". A service pinned to a computer that is asleep and may be woken is "down, wakeable" (`wakeable: true`): Nova may wake that computer for models, never for a service. (2) On Windows, the device agent now reads each wired card's Wake-on-LAN instead of always `unknown`: a card Windows won't let wake the computer (`powercfg /devicequery wake_armed`, which needs no administrator) is `off`, so a wake isn't sent that can't work and the Models screen says why; a card is `magic` only when Windows also says its magic packet is on, else `unknown`. Wi-Fi stays `unknown`, as on Linux.
- What you can now do: set a computer to sleep when idle without services moving onto it, and see on a Windows computer when its network card has waking turned off.
- Still unfinished: on Windows, reading the magic-packet setting itself often needs an administrator, so an armed card usually reads `unknown` (never blocks a wake). A service never wakes a computer: that stays inference routing's job, per the ADR.
- Checked: new tests in tests/core/services-placement.test.ts (sleeps-by-design placement, down-wakeable, unchanged without sleep choices) and tests/core/wol-golden.test.ts (the Windows reading, by MAC, with odd output). The Windows command's output format was checked once, read-only, on this build machine. Lint, typecheck and npm test ran in iso.sh.
