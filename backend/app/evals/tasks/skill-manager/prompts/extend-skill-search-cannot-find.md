We keep shipping tools with descriptions no agent can act on, so I want the rule written down where the next person writing one will find it.

Four things it has to say. The name and the opening line describe what the tool DOES, not what it is. It says what comes back. It names the failure modes — what an `Error:` from that tool actually means for the caller's next step, and what the tool does not do even when it succeeds. And it says when NOT to reach for it, naming the tool that is the right one instead.
